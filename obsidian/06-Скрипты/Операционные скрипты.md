## init_admin.py

Provision пароля администратора панели.

| Режим | Команда |
|-------|---------|
| Интерактивно | `python scripts/init_admin.py` |
| Пароль в CLI | `python scripts/init_admin.py --password "..."` |
| Только Argon2id-hash | `python scripts/init_admin.py --hash-only "..."` → вставить в `ADMIN_PASSWORD_HASH` |

Поведение: создаёт/чинит `admin` в `app_users`, Argon2id-хэш. При реальной смене увеличивает token_version. Bootstrap из env принимает Argon2id/bcrypt и применяет каждое новое значение ADMIN_PASSWORD_HASH однократно. Интерактивный ввод предпочтительнее аргументов командной строки. См. [[ADR-005 Argon2id Migration]].

См. [[API Auth]] · [[music.env]]

## create_session.py

Интерактивная генерация **Telegram MTProto session string**.

```powershell
python scripts/create_session.py
```

1. Запрашивает api_id / api_hash / телефон / код
2. Выводит session string
3. Далее: `secure_tg_accounts` / запись в `tg_accounts` / миграция

Используется при новом кластере и при **ротации SESSION_SECRET** (старые сессии становятся нечитаемыми).

См. [[Telegram кластер]]

## secure_tg_accounts.py

Шифрование/аудит `session_string` и `api_hash` в БД.

| Команда | Эффект |
|---------|--------|
| `python scripts/secure_tg_accounts.py` | Fernet-seal plaintext полей |
| `python scripts/secure_tg_accounts.py --check` | Только отчёт, без изменений |

Зависит от `SESSION_SECRET` в `music.env` и доступной PostgreSQL.

## migrate_data.py

## VFS Import из SQL backup

Для переноса новых музыкальных папок из Replit используй админ-панель T-Music: **VFS → Импорт из резервной копии Replit**. CLI `migrate_data.py` предназначен для offline-миграции живой исходной БД и не принимает SQL dump.

- Загрузи только plain PostgreSQL SQL dump.
- Сначала получи preview и проверь source path, counts и conflicts.
- Импортируются только `folders`, `folder_closures`, `vfiles`; credentials и DDL не переносятся.
- SQL не исполняется; staging хранится в `data/vfs_imports/` до 1 часа.
- Перед запуском сделай backup текущей `tgmusic`.

Подробнее: [[Импорт VFS из SQL]].

## warm_cover_cache.py

Бэкфилл локального кеша обложек после перехода на cache-only показ (2026-10-03).
Карточки отдают `?key=`, поэтому строки каталога, обогащённые раньше, нуждаются
в файлах `{key}.bin` на диске — иначе показ даст 404 без сетевого фолбэка.

```powershell
python scripts/warm_cover_cache.py --dry-run
python scripts/warm_cover_cache.py --limit 500
python scripts/warm_cover_cache.py
```

Собирает distinct `music_artists.image_url` + `music_albums.cover_url`,
пропускает уже кешированные без сети, остальные качает один раз
(`fetch_and_cache`, concurrency 4). БД не пишет, секреты не печатает.
Повторный запуск безопасен. См. [[API Library]] · [[Кэш и стриминг]].

## backup_project.py — бэкап исходников (2026-10-16)

Резервная копия кода проекта в ZIP: только то, что нужно для запуска, сборки и
разработки. Стандартная библиотека, без зависимостей; работает и на Windows, и на
Linux (VPS). Рядом с архивом пишется `*.manifest.txt` — дата, `git HEAD`, состав,
размеры, SHA-256 архива и напоминание про секреты.

```powershell
python scripts/backup_project.py                  # архив рядом с проектом (<root>/../tmusic-backups)
python scripts/backup_project.py --list           # только показать состав, ничего не создавать
python scripts/backup_project.py --label before-upgrade
python scripts/backup_project.py --keep 10        # хранить 10 последних (0 = не удалять, по умолчанию)
python scripts/backup_project.py --with-secrets   # music.env → ОТДЕЛЬНЫЙ архив
python scripts/backup_project.py --with-git --with-runtime
```

| Режим | Что добавляет |
|-------|---------------|
| (по умолчанию) | Код `backend`/`frontend`/`mobile`/`scripts`, тесты, конфиги запуска, `obsidian/`, `.sec_audit/`, корневые отчёты `*.html` |
| `--with-secrets` | Отдельный `*.secrets.zip` с `music.env`, `.secrets/`, `mobile/android/keystore.properties` — не шифрован, в git/облако не выкладывать |
| `--with-git` | История `.git` |
| `--with-runtime` | `data/` (дампы БД), `cache/`, `frontend/dist` |

Не попадает никогда: `node_modules`, `__pycache__`, `.pytest_cache`, `.ruff_cache`,
`frontend/dist`, `mobile/android/build`, `.gradle`, `data/`, `cache/`, `backend/storage`,
логи, `*.apk`, дампы/`*.db`, бинарники ffmpeg (`backend/app/utils/ffmpeg/*.dll|exe` —
скачиваются заново при первом транскодинге), `music.env` и прочие секреты.
Список включаемых путей — константа `INCLUDE_PATHS` в самом скрипте (allowlist,
а не «всё минус исключения»), исключения — `EXCLUDE_DIR_NAMES` /
`EXCLUDE_FILE_PATTERNS`.

Скрипт не удаляет ничего, кроме старых архивов **этого** проекта при явном `--keep`;
после записи проверяет архив (`testzip`) и наличие обязательных файлов, иначе
удаляет битый результат. Прежний вариант на PowerShell —
`scripts/backup_project.ps1` (+ `backup_project.bat`): он шире по составу (включает
`music.env` и `.git` по умолчанию) и умеет шифровать ZIP через 7-Zip (`-ZipPassword`).
Backup БД — отдельная история: `pg_dump` по расписанию в `backup_scheduler.py`.

Проверено 2026-10-16: 392 файла / 3.3 МБ → ZIP 1.2 МБ, 392 записи; восстановление
побайтово совпало по выборочным файлам (включая кириллические имена), мусора после
распаковки нет.

## Типовой ops-процесс (fresh install)

```powershell
# 1. Config
copy music.env.example music.env
# заполнить DATABASE_URL, SECRET_KEY, SESSION_SECRET, ADMIN_PASSWORD_HASH, TG_*

# 2. DB
psql -c "CREATE DATABASE tgmusic ..."

# 3. Optional migrate
python scripts/migrate_data.py

# 4. Admin (если нет hash в env)
python scripts/init_admin.py --password "StrongPass123"

# 5. Optional new TG session
python scripts/create_session.py

# 6. Run
.\start_tmusic.bat

# 7. Verify
python scripts/secure_tg_accounts.py --check
```

## Обработка пустых архивов логов

`scripts/extract_logs.py` выбирает первый недиректорный ZIP member. Пустой или directory-only архив возвращает exit 1 с понятным сообщением, без IndexError/traceback. Значения паролей в сообщение не выводятся. См. [[Ревью граничных значений 2026-10-01]].
