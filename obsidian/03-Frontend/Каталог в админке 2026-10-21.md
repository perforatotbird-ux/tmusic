# Каталог в админке 2026-10-21

> **Симптом (владелец):** «В админке сломано отображение Каталога. Альбомы отображаются в списке как Артист.»

Связано: [[API Library]] · [[Операционные скрипты]] · [[Курирование обложек и имён]] · [[00-Главная]]

## Что видел владелец

Вкладка **Каталог** (`AdminPanel` → `AdminCatalog`) показывала плоский список, в котором первые
страницы целиком состояли из папок-альбомов:

```
(2020) Нечего ждать        Артист · 1 альб.   (родитель: 02.Singles)
2022 - Град обреченный     Артист · 1 альб.   (родитель: Son, Fire!)
1987 - Дуля с маком        Сборник · 1 альб.  (родитель: 01 - Albums)
```

Реальные артисты при этом уезжали на дальние страницы (в каталоге 291 корневая карточка и
2 756 вложенных).

## Две независимые причины

### 1. Список админки не знал про иерархию

`AdminCatalog` запрашивал `/api/admin/catalog/artists` **без** `root_only`/`parent_id`, то есть
получал все уровни дерева одним плоским списком (постранично по 500, до 20 000). Публичная
библиотека так не делает: `GET /api/library/artists` при отсутствии поиска сам ставит
`root_only=True` и ходит по уровням. Итог: карточки альбомов, лежащие внутри артиста, выглядели
как карточки верхнего уровня.

### 2. Синхронизация дерева выводила `kind` из формы папки

`CatalogAdminService.sync_catalog_folder_tree` (коммит `9eccd18`, скрипт `sync_nested_catalog.py`)
классифицировал узлы так:

```python
is_compilation = len(subfolders) > 0
kind = "compilation" if is_compilation else "artist"
```

В дискографии (`Артист → «01.Albums» → альбом → «Covers»`) папка альбома — это релиз, но
«есть подпапки» делало её **Сборником**, а «лист с аудио» — **Артистом**. Именно поэтому альбомы
в списке читались как «Артист». Дополнительно: счётчик файлов учитывал и картинки, поэтому
папка `Covers` внутри альбома тоже превращала релиз в «контейнер».

## Что исправлено

### Backend

| Файл | Правка |
|---|---|
| `app/repositories/artist_repository.py` | `list_artists(..., parent_id=...)` — выборка прямых детей одной карточки |
| `app/services/music_library_service.py` | проброс `parent_id`; новый `CatalogAdminService.classify_node_kind(depth, has_direct_audio, has_child_audio, catalog_kind)`; в синхронизации считаются **только** файлы `mime_type LIKE 'audio/%'` |
| `app/api/admin_catalog_router.py` | `GET /api/admin/catalog/artists?parent_id=` |

Правило классификации (`classify_node_kind`):

| Узел | `kind` |
|---|---|
| корень дерева | задаётся вызывающим (`catalog_kind`) |
| есть своё аудио, ниже аудио нет | `standalone_album` |
| всё остальное (группировка, бокс-сет, папка артиста) | `genre_collection` |

`compilation` больше не выводится из формы папки — этот тип означает мульти-артист сборник.

### Frontend — `components/AdminCatalog.jsx`

- Список ходит **по одному уровню**: наверху `root_only: true`, внутри карточки — `parent_id`.
  Поиск по-прежнему идёт по всему каталогу (иначе вложенные карточки стали бы недоступны).
- Хлебные крошки `Каталог › … › карточка` + кнопка «Назад» (`goToLevel`).
- У карточки с вложениями появилась кнопка `FolderOpen` и пункт меню «Открыть вложенные (N)».
- В строке видно `N влож.`, а в результатах поиска — `↳ родитель`.
- «Новая карточка» создаётся на текущем уровне (`parent_id` текущей карточки).
- «Переместить в…» грузит плоский список целей по первому фокусу — цель может быть на любом уровне.

## Массовое удаление отмеченных карточек

Кнопка **«Удалить выбранные (N)»** в строке групповых действий (рядом с «Закрепить»/«Разблокировать»).

- Работает по чекбоксам `selectedArtists` текущего уровня; перед удалением — `useConfirm` с перечислением последствий.
- Карточка удаляется **целиком** (решение владельца 2026-10-21): её альбомы уходят вместе с ней, ничего не блокирует удаление. Аудиофайлы не трогаются — остаются в VFS, папка сохраняется, карточку можно вернуть сканированием.
- Один запрос `POST /api/admin/catalog/artists/batch-delete` (`adminApi.batchDeleteArtists`). Бэкенд возвращает `deleted`, `deleted_albums` и `skipped` (только `not_found`/`refused`/`error`), поэтому одна проблемная карточка не отменяет всю пачку.
- Одиночное удаление из меню ⋮ идёт через `DELETE …?with_albums=true` и обновляет состояние так же.
- **Состояние обновляется сразу:** ответ → мгновенная вычитка строк из `artists` (и кэшей `albumsByArtist`/`tracksByAlbum`, `expanded`, `editingArtist`) → тихий рефетч уровня `loadArtists({ silent: true })` без мигания «Загрузка…» → `bustCatalogCache()` → `emitCatalogChanged({action:'cards-deleted'})`, чтобы грид библиотеки и шторка альбома за панелью сбросили удалённые карточки. Свой же листенер этот action игнорирует, иначе список перезагружался бы дважды.
- Баннер сообщает: `Удалено карточек: N (альбомов: M).` (+ `Пропущено: …` для `not_found`/ошибок).
- Вложенные карточки не удаляются каскадом: `delete_artist` открепляет детей (`parent_id = NULL`), они остаются в каталоге.

Защита от регрессий: `frontend/tests/admin-catalog-bulk-delete.test.cjs` и
`backend/tests/test_admin_catalog.py::test_batch_delete_removes_cards_with_albums_and_detaches_children`.
