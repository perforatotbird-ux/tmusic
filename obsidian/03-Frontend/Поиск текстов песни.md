## Симптом

Панель «Текст песни» в полноэкранном плеере почти всегда показывает
«Текст не найден для этого трека».

## Диагностика (на реальных данных)

Проверено на выборке имён файлов из таблицы `vfiles` и живыми запросами к LRCLIB.

Имена в библиотеке грязные — номер трека стоит **до** артиста:

| Файл в `vfiles` | Что уходило раньше | Что уходит теперь |
|---|---|---|
| `05. Красные Звёзды - Так и будет.mp3` | track = `Красные Звёзды - Так и будет` | artist `Красные Звёзды`, track `Так и будет` |
| `14 Группа  ОРЗ - Сцена коварного заговора.mp3` | то же | artist `Группа ОРЗ`, track `Сцена коварного заговора` |
| `TYP808 - Шайка Дурачков 31.tmp.mp3` | двойное расширение | artist `TYP808`, track `Шайка Дурачков 31` |
| `- 01_Kogda_Pridet_Prazdnik(...).mp3` | `_` в имени | подчёркивания → пробелы |
| `09 - For The Punx.mp3` | artist = `09` | artist `null` (это номер, не артист) |

### Три причины промаха

1. **Клиент делил имя по ПОСЛЕДНЕМУ `" - "`, но только когда артист уже известен.**
   При `05. Красные Звёзды - Так и будет.mp3` в `track` уходило
   `Красные Звёзды - Так и будет` — такой строки в LRCLIB нет.
2. **Плейсхолдеры артиста считались настоящим именем.**
   `T-Music`, `Недавнее`, `Офлайн кэш`, `Кэш устройства` отправлялись в LRCLIB
   как `artist_name` и гарантировали промах.
3. **`/api/get` у LRCLIB точный по КАЖДОМУ параметру.** Один неверный
   `album_name` → 404, даже если песня есть. Старый код делал ровно один
   запрос и сразу падал в поиск.

## Стратегия

### Клиент — `frontend/src/utils/lyricsQuery.js`

Разбор имени файла в `(artist, track)`:

1. снять расширение, в том числе двойное (`.tmp.mp3`);
2. убрать ведущий номер трека (`01`, `01.`, `01 -`, `#1`, `-`);
3. `_` → пробел;
4. делить по ПОСЛЕДНЕМУ сепаратору — составные артисты не режутся
   (`Vnuk, Vion & Vobula - Вова Петергоф`);
5. снять шум `[СБК]`, `(live)`, `(2008)`;
6. `NN - Title` без артиста → `artist = null`, а не `NN`.

Приоритет артиста: **каталог важнее имени файла**; плейсхолдеры отбрасываются.
Дублирующий префикс артиста в названии снимается. `fileName` передаётся всегда —
это позволяет бэкенду повторить разбор при промахе.

### Бэкенд — `lyrics_service._lookup_upstream`

Ступенчатый сброс ограничений вместо одного запроса:

| Шаг | Запрос |
|-----|--------|
| 1 | `/api/get` artist + title + album |
| 2 | `/api/get` artist + title (альбом не совпал) |
| 3 | `/api/search` `"artist title"` |
| 4 | `/api/search` только title (артист неизвестен или не подтвердился) |

Ранжирование выдачи: сначала синхронизированный текст, затем точное совпадение
артиста, затем минимальная разница длительности.

### Честный UI

Пустое состояние показывает, **что именно искалось**: `Искали: Артист — Название`.
Промах теперь диагностируем, а не непрозрачен.

## Проверки

1. `frontend/tests/lyrics-query.test.cjs` — 21 тест, все имена файлов взяты
   дословно из `vfiles`.
2. `backend/tests/test_lyrics.py` — 13 тестов: ступенчатый откат, ранжирование,
   фильтрация мусорных узлов, отсутствие пробрасывания исключений.
3. Живая проверка LRCLIB: `Enter Sandman` + артист `Metallica` → 200,
   синхронизированный текст. `Isolation.mp3` без артиста → текст найден через
   поиск. Русские треки (`Красные Звёзды`, `Thunderclash`) дают 0 совпадений.

**Важно:** русскоязычные треки этой библиотеки **отсутствуют в LRCLIB** — 0
результатов по `/api/search`. Форма запроса корректна, но данные отсутствуют
upstream. Для них нужен другой провайдер или локальные `.lrc`/`.txt` рядом с
аудио (не реализовано).

4. `backend`: `pytest` → 402 passed, 1 skipped.
5. `frontend`: `npm test` → 125/131; 6 падений предсуществующие
   (SSE-транскод, `confirm` в VFS-импорте, 429 c HTTP-date) — проверено
   `git stash` на чистом дереве.
