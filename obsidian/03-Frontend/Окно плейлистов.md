# Окно «Плейлисты» — редактор названия и содержимого

#tmusic #frontend #playlists

Связано: [[Обзор Frontend]] · [[API Library]] · [[Карта репозитория]] · [[Чеклист разработки]] · [[00-Главная]]

## Что изменилось (2026-10-12)

Пункт **«Плейлисты»** в выпадающем меню профиля теперь открывает **отдельное окно**
(`frontend/src/components/PlaylistsModal.jsx`), где плейлист редактируется целиком:
и название, и содержимое.

Раньше этот пункт включал встроенную панель `LibraryPanel` (`section='playlists'`) в
области библиотеки — только создание, удаление, порядок треков и воспроизведение,
без переименования и без добавления треков.

## Возможности окна

| Действие | Как в UI |
|----------|----------|
| Список плейлистов | левая колонка (на узком экране — первый экран) |
| Создать | поле «Новый плейлист» + «Создать» (Enter тоже работает) |
| Переименовать | поле названия + «Сохранить»; кнопка активна только при изменении |
| Удалить плейлист | иконка в строке списка или кнопка «Удалить» — с подтверждением |
| Слушать | «Слушать» — весь плейлист в очередь; клик по треку — с этой позиции |
| Добавить треки | поиск по медиатеке (`/api/search/tracks`), кнопка «+» у результата |
| Убрать трек | иконка корзины в строке трека |
| Порядок треков | drag-and-drop или кнопки ↑↓; порядок сохраняется сразу |

На широком экране окно двухпанельное, на узком — список и содержимое поочерёдно
с кнопкой «К списку плейлистов». Окно построено на общем `components/ui/Modal.jsx`
(фокус-ловушка, Escape, блокировка прокрутки, safe-area).

## Backend

**Новый эндпоинт:** `PATCH /api/playlists/{playlist_id}` (auth) — тело `{name}`,
схема `PlaylistName` (trim, 1–120 символов). Переименовывает только плейлист текущего
пользователя; чужой/несуществующий → `404`. Ответ — `PlaylistSummary`; список треков
не затрагивается.

Реализация: `playlist_service.rename_playlist()` — валидация и границы транзакции в
сервисе, доступ к данным через `PlaylistRepository.get(..., for_update=True)`.

Остальные эндпоинты, которыми пользуется окно, уже существовали:
`GET/POST /api/playlists`, `GET/DELETE /api/playlists/{id}`,
`POST /api/playlists/{id}/items`, `DELETE /api/playlists/{id}/items/{item_id}`,
`PUT /api/playlists/{id}/items/order`.

## Ограничения и открытые пункты

- Встроенная панель плейлистов в `components/HomeExtraPanels.jsx` (`section='playlists'`)
  осталась как **legacy**: из меню она больше не открывается, но её покрывают два
  regression-теста в `tests/error-handling.test.cjs`. Убирать её нужно вместе с этими
  тестами — отдельной задачей, в этом изменении не трогали.
- Браузерный E2E-прогон окна не выполнялся: node/Playwright в песочнице агента не
  запускается. Проверены production-сборка и логика обработчиков; UI-smoke на рабочем
  стенде — за владельцем.
- Escape при открытом вложенном диалоге подтверждения закрывает и его, и окно. Это общее
  поведение `useConfirm` + `ui/Modal` во всём приложении, не специфика этого окна.
- Изменения локальные: commit/push/deployment не выполнялись, CORS не затрагивался.
