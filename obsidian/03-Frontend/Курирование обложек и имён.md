# Курирование обложек и имён

#tmusic #frontend #admin

Запрос владельца (2026-10-12): «Сделай возможность Админу в UI изменять карточку
и имя любого элемента коллекции» + баг «если назначить артисту обложку вручную —
эта обложка применяется для каждого альбома».

Решения владельца: подстановку обложки артиста в альбомы **убрать полностью**;
редактирование доступно **и в админке, и в каталоге**.

---

## 1. Баг: обложка артиста протекала в альбомы

Корень — `frontend/src/utils/cover.js`, введён в `ac683db`:

```js
// было
export function resolveCoverUrl(entity, artist = null, fallback = DEFAULT_COVER) {
  const own = entity?.custom_image_url || entity?.cover_url || entity?.image_url || null
  const artistFallback = artist?.custom_image_url || artist?.image_url || null
  return firstTruthy(own, artistFallback, fallback)
}
```

`renderAlbumCard(album, artist)` передавал артиста вторым аргументом → каждый
альбом без своей обложки получал обложку артиста, включая назначенную вручную.

Стало:

```js
export function resolveCoverUrl(entity, fallback = DEFAULT_COVER) {
  const own = entity?.custom_image_url || entity?.cover_url || entity?.image_url || null
  const safeFallback =
    fallback === null || typeof fallback === 'string' ? fallback : DEFAULT_COVER
  return firstTruthy(own, safeFallback)
}
```

- второй аргумент — теперь **fallback**, а не источник-родитель;
- `null` остаётся значимым («без fallback» — на это опирается метаданные
  очереди: сохранённый `/icon.svg` маскировал бы бейдж «нет обложки»);
- не-строковый `fallback` (например, объект артиста от старого вызова)
  игнорируется и никогда не попадает в `<img src>`.

Обновлены все 14 точек вызова: `MusicLibrary.jsx` (678, 689, 698, 735, 739, 910,
922, 927, 964, 1033, 1333), `AlbumDetail.jsx` (102, 244, 253).

Тесты: `frontend/tests/cover.test.cjs` — 9 тестов, включая регрессию
«альбом без своей обложки НЕ наследует обложку артиста».

## 2. Обложка трека: третий уровень каталога

`VFile` не имел `custom_image_key` — треки были единственным уровнем без своей
обложки. Добавлено:

- колонка + индекс `idx_vfiles_custom_image_key` в `ensure_catalog_schema()`
  (аддитивная миграция на старте, как `music_artists.parent_id`);
- `MusicLibraryService.set_custom_cover()` принимает `target_type='track'`
  (иначе 400, отсутствующая сущность 404);
- `TrackResponse.custom_image_url` — чтобы обложка доходила до альбомного
  списка (`stream_service.build_track_responses`, колонка добавлена в
  `_TRACK_LIST_COLUMNS`, чтобы не получить N+1);
- `search_repository.search_tracks`: `t.custom_image_key or meta.custom_image_key`
  — своя обложка трека приоритетнее унаследованной от альбома.

## 3. Переименование трека

`VFile.name` — это и есть отображаемое название трека (отдельной колонки нет),
поэтому переименование идёт через `PATCH /api/admin/vfs/files/{file_id}`:
в схему `FileUpdate` добавлено поле `name` (min 1, max 500; пустое после trim →
400). Эндпоинт уже был admin-only и с аудитом, так что новых маршрутов не
понадобилось.

`_file_payload()` теперь отдаёт `custom_image_url` — тот же контракт, что у
карточек артистов/альбомов.

## 4. UI

| Место | Что доступно |
|-------|--------------|
| `AdminCatalog.jsx` | В меню альбома — пункт «Треки»: список треков с инлайн-переименованием и кнопкой обложки. У артистов/альбомов — как было (переименование + обложка) |
| `AlbumDetail.jsx` (каталог) | «Переименовать» в шапке альбома; в меню ⋮ трека — «Переименовать трек» и «Обложка трека»; обложка трека показывается миниатюрой в строке |
| `MusicLibrary.jsx` (каталог) | «Переименовать» рядом с именем артиста в шапке (админ, не для «В кэше») |
| `CoverPicker.jsx` | Не менялся — принимает `type: 'track'` через тот же `target` |

Общая валидация — `utils/adminEdits.js::trackRenamePatch(draft, current)`:
trim, пустое или неизменённое → `null` (no-op вместо лишнего PATCH). Тесты:
`frontend/tests/admin-edits.test.cjs`.

Обновление после смены обложки: `App.jsx` шлёт `tmusic:catalog-changed`;
`AlbumDetail` слушает его и перечитывает треки на месте (без reload и без
вспышки «Загрузка треков»).

## Связанное: кнопка «Сканировать»

Курирование и сканирование пересекаются в одном месте: **ручная обложка
неприкосновенна**. Скан пропускает альбомы с `custom_image_key` и не затирает
`image_url` артиста, если там уже настоящая картинка. Разбор бага «Сканировать
ничего не выполняет» (placeholder-обложки Last.fm, схлопывание ключей кеша,
отчёт о результате в UI) — в [[Сканирование каталога]].

### Popup-прогресс сканирования (левый верхний угол)

Жалоба 2026-10-12: «Должен быть всплывающий в левом верхнем углу Progress bar со
статусом получения обложек». Скан стал фоновой задачей
(`scan_service`), и её прогресс показывает `ScanProgressHost`, смонтированный в
`App.jsx` — то есть **вне** экрана админки, поэтому бар не исчезает при уходе со
страницы. Детали, включая `pointer-events`, `role="progressbar"`,
неопределённую стадию и `tmusic:catalog-changed` по завершении, —
в [[Сканирование каталога]] §3–§4.

## 5. Два бага смены обложек (жалоба 2026-10-12)

Владелец: «В админке меняю картинку для выбранного артиста, указываю прямую
ссылку — устанавливается другая картинка из кеша, которую я ставил предыдущему
артисту. И в интерфейсе нет возможности изменить обложку для артиста, альбома
или сборника.»

Разобрано на два независимых дефекта — фронтенд и бэкенд.

### 5.1 «Изменить обложку негде» — действия были спрятаны

Точки входа **существовали**, но все — за косыми меню «⋮»:

| Поверхность | Где было | Что стало |
|-------------|----------|-----------|
| `AdminCatalog.jsx` | `⋮ → Изменить обложку` у артиста и альбома | видимые кнопки-значки в строке рядом с `⋮` (пункт меню оставлен) |
| `MusicLibrary.jsx`, карточка альбома | только внутри `AlbumDetail` | кнопка `.tmusic-card-cover-btn` на самой карточке (top-right, поверх обложки) |
| `MusicLibrary.jsx`, карточка артиста/сборника | только на странице артиста | кнопка на аватаре карточки (top-right) |

Правила видимости: только админ, и никогда для «закешированных» сущностей
(`is_cached_group` / `is_cached_album`) — там некуда писать. Обе кнопки проходят
те же hover/focus/touch-правила, что и `.tmusic-card-play-btn`: `@media (hover:none)`
показывает всегда, `:focus-within` и `:focus-visible` не оставляют кнопку
невидимой для клавиатуры (WCAG 2.4.7 / 1.4.11).

`CoverPicker` теперь называет уровень и id цели («Артист / сборник · #147») —
при открытии пикера подряд для разных карточек это снимает неоднозначность.

### 5.2 «Ставится картинка предыдущего артиста» — две причины

**(а) Админка не слушала событие.** `MusicLibrary` и `AlbumDetail` обновлялись по
`tmusic:catalog-changed`, а `AdminCatalog` — нет: сохранённая обложка попадала в
БД, но строка списка продолжала показывать **прежнюю** картинку. Для админа,
который только что редактировал соседнего артиста, это буквально «установилась
обложка предыдущего артиста». Добавлен listener: `loadArtists()` + перечитка
альбомов уже раскрытых артистов, **без** `refresh()` — иначе сворачивалась
раскрытая ветка посреди редактирования.

**(б) Ручная обложка брала байты из URL-кеша.** `POST /api/library/cover` шёл через
`fetch_and_cache`, который cache-first: ключ URL = `sha1(scheme://netloc/path)`
(**без query**), кеш перманентный. То есть байты, сохранённые ранее для другого
контекста (обложка альбома из авто-энричмента, старая версия того же URL),
могли быть сохранены как «ручная обложка». Разделено на `fetch_and_cache`
(обогащение, cache-first) и `fetch_fresh` (ручной выбор — всегда скачивает, но
всё равно пишет URL-запись). Подробности и таблица — в [[Кэш и стриминг]].

Shipped-событие перестало быть безымянным: `libraryApi` теперь шлёт
`tmusic:catalog-changed` c `detail: {type, id, custom_key}` (раньше — пустой
`CustomEvent`), поэтому listener может патчить конкретную строку.

### Проверки

Живой прогон через реальный HTTP-путь (сеть — только `is_safe_host`/`_fetch_safe`):
- два артиста, два разных URL → у каждого **своя** картинка (разные ключи и
  байты);
- тот же URL уже лежит в URL-кеше с **другими** байтами → ручная обложка
  сохраняет новые байты, а не кеш-запись.

Frontend suite **191 passed** (+9 `tests/cover-curation-wiring.test.cjs`):
метки уровней пикера, наличие listener-а в `AdminCatalog`, видимые кнопки на
строках админки и карточках каталога, gating по `isAdmin` и `is_cached_*`,
hover/focus/touch для `.tmusic-card-cover-btn`, ремаунт пикера по `key`.

Backend: `tests/test_disk_cache.py` (13) — обход URL-кеша в `fetch_fresh`, ключ от
содержимого, заблокированный хост; полный suite **455 passed / 5 skipped**
(единственный сбой — прежняя флакость rate-limit).
