## Как запускать

```powershell
# из backend/: обязательная одноразовая схема (создаётся и удаляется conftest)
cd K:\Test\tmusic\backend
$env:TMUSIC_TEST_SCHEMA = "tmusic_test"
python -m pytest tests/ -q
```

Без `TMUSIC_TEST_SCHEMA` прогон против живой БД отклоняется. Явный
`TMUSIC_ALLOW_LIVE_DB_TESTS=1` — только осознанно и разрушительно.

Требования: `backend/requirements.txt` + `backend/requirements-dev.txt`
(`pytest`, `pytest-asyncio`, `httpx`) и PostgreSQL. Схема создаётся пустой,
таблицы — из моделей; тесты, которым нужен мигрированный каталог
(`test_library.py`, `test_library_null_search.py`, один кейс `test_api.py`),
помечены skip в изолированной схеме.

Актуальный результат 2026-10-21: **505 passed, 10 skipped** в одноразовой
PostgreSQL-схеме; `ruff check backend/app backend/tests` — чисто.

Frontend: `npm test` в `frontend/` (Node built-in runner, `tests/*.test.cjs`).

> Приёмы, которые стоит переиспользовать в новых тестах каталога:
> - сканирование в тестах идёт **без сети** — `cover_cache.fetch_and_cache`
>   подменяется async-recorder-ом, который просто записывает URL-ы;
> - `lastfm_service.get_artist_info` / `get_album_info` стабы обязаны принимать
>   `force=False`: эндпоинт скана вызывает их с `force=True`;
> - тестовые сущности создаются через `CatalogAdminService.create_collection` +
>   прямой `MusicAlbum(folder_id=…, artist_id=…)` (в `AlbumRepository` нет
>   `create`), удаляются в `finally` вместе с папкой;
> - `test_lastfm.py` — чистые unit-тесты guard-ов (`is_placeholder_image`,
>   `pick_image`, `clean_bio`, `_sanitize_cached`), БД не нужна.

> Известная флакость: `test_error_handling_fixes.py::test_tree_import_*` падает с
> 429, если весь suite идёт одним процессом — бюджет `_import_budget` (4 запуска
> импорта в минуту на пользователя) расходуется соседними тестами. По отдельности
> и по файлу проходит (44 passed); к изменениям каталога отношения не имеет.

> Live-suite меняет данные и пароль `admin`, поэтому по умолчанию запрещён.
> Штатный режим — `TMUSIC_TEST_SCHEMA=<schema>`: conftest создаёт схему,
> bootstrap-ит admin `123` только внутри неё и удаляет схему после прогона.
