## Уровни кэширования

| Уровень | Где | ТTL / лимит | Назначение |
|---------|-----|-------------|------------|
| **RAM audio** | `ram_cache_service` | LRU: 15 треков / **512 МБ** | Повтор play без TG round-trip |
| **Pre-cache (UI)** | `playerStore` + browser `fetch` | 2×2 МБ + 512 КБ «хвост», по shuffle-порядку | Упреждающая загрузка; принимается только HTTP 206 |
| **Covers disk** | `cache/music_covers` | **TTL=0** (перманентно) | Не теряются после reboot |
| **Cover HTTP cache** | headers | ETag + cache-control (`utils/http.py`) | 304 на повторы |
| **External provider disk** | `core/disk_cache` (`cache/external/`) | lyrics 90 дн / lastfm 14 дн / negative 15 мин | Не долбить LRCLIB и Last.fm |
| **Клиентский API-cache** | `src/api/cache.js` | catalog 5м · stats 10м · tracks/vfs 2м + single-flight | Убрать дубли запросов грида/плеера |
| **Cover presence** | `services/coverMissing.js` (Set) | до bust мутацией | Не переспрашивать `/covers/manifest` |
| **SW shell/covers** | `public/sw.js` | cache-first `/assets/*` (cap 24) · covers LRU 120 | Офлайн-шелл, мгновенные обложки |
| **Player localStorage** | `tmusic_session` / `tmusic_durations` | session-live / cap 400 | F5 не сбрасывает очередь; длительности |

## Внешний disk-cache (LRCLIB / Last.fm)

Модуль `backend/app/core/disk_cache.py` — общий JSON-кеш на диске для «тяжёлых» внешних ответов.

| Свойство | Реализация |
|----------|-----------|
| Ключ | `sha256(namespace + canonically-serialized payload)[:32]`, payload — разрешённая идентичность (casefold для lastfm, parse_track_meta для lyrics) |
| Namespaces | `lyrics` (90 дн, 20 МБ/5000), `lastfm` (14 дн, 5 МБ/5000) — изолированы, бюджеты per-namespace |
| Негативный кеш | `value=null` живёт `NEGATIVE_TTL_SEC` (15 мин) — трек без текста не вызывает LRCLIB дважды при каждом открытии |
| Eviction | по mtime файла; hit продлевает «свежесть» доступа → LRU без памяти процесса |
| Запись | атомарно `.tmp` → `os.replace`; битый JSON читается как miss |
| Интеграция | `lyrics_service._lookup_upstream` / `lastfm_service._fetch_*` — сеть; публичные `get_lyrics`/`get_artist_info`/`get_track_info` — кеш-обёртки |
| Admin | `GET /api/admin/cache/stats`, `POST /api/admin/cache/flush?kind=external|ram|all&namespace=` (с аудит-логированием) |

Тесты: `tests/test_disk_cache.py` (11 шт) + автофикстура `conftest.py`, перенаправляющая `external_cache.root` в tmp на каждый тест (иначе негативные записи перетекают между запусками и глушат сетевые стабы).

## Клиентский кеш API (single-flight)

`frontend/src/api/cache.js` — общий слой для `library.js`, `stream.js`, `vfs.js`:

- `memoize(key, ttl, fetcher)` — параллельные вызовы одного URL ждут **один** запрос; свежий ответ не идёт в сеть;
- `bustMediaCaches()` — сбрасывает `/api/library`, `/api/stream`, `/api/vfs` одним контрактом;
- `bustCatalogCache()` (экспорт из `library.js`) = `bustMediaCaches()` + `resetCoverProbes()` — единственная точка инвалидации для всех мутаций каталога, rename, cover-ops и VFS-импорта (событие `tmusic:vfs-imported`).

## RAM Cache (DoS-защита)

Конфиг:
- `RAM_CACHE_MAX_ITEMS` (default 15)
- `RAM_CACHE_MAX_BYTES` (default 512 * 1024 * 1024)

LRU вытесняет старые треки при превышении **любого** из лимитов. Защита от OOM через забивание кэша.

## Range + AES-256-GCM

1. Клиент шлёт `Range: bytes=a-b`
2. `stream_service.get_track_size` возвращает **plaintext** size
3. Блоки расшифровываются on-the-fly (`decryption_service`) при `vfile.is_encrypted`
4. Ответ **206** с корректным `Content-Range`

Ключи vault:
- `ENCRYPTION_RECOVERY_KEY` (primary)
- `ENCRYPTION_FALLBACK_KEYS` (legacy tracks)

См. [[music.env]] · [[Архитектура]]

## Auth для `<audio>`

HTML5 `<audio>` не шлёт Authorization. Same-origin cookie-сессия принимается backend для основного URL. Для клиентов без cookie:
1. SPA вызывает `POST /api/stream/token` → short-lived JWT
2. `audio.src = /api/stream/{id}?token=...`
3. query-путь принимает только `scope=stream`; session JWT в URL запрещён

См. [[API Stream]] · [[ADR-004 Cookie Auth CSRF]]
