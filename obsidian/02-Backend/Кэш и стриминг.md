## Уровни кэширования

| Уровень | Где | ТTL / лимит | Назначение |
|---------|-----|-------------|------------|
| **RAM audio** | `ram_cache_service` | LRU: 15 треков / **512 МБ** | Повтор play без TG round-trip |
| **Pre-cache (UI)** | `playerStore` + browser `fetch` | 2 МБ × следующие 2 трека | Упреждающая загрузка; принимается только HTTP 206 |
| **Covers disk** | `cache/music_covers` | **TTL=0** (перманентно) | Не теряются после reboot |
| **Cover HTTP cache** | headers | ETag + cache-control (`utils/http.py`) | 304 на повторы |

---

## RAM Cache (DoS-защита)

Конфиг:
- `RAM_CACHE_MAX_ITEMS` (default 15)
- `RAM_CACHE_MAX_BYTES` (default 512 * 1024 * 1024)

LRU вытесняет старые треки при превышении **любого** из лимитов. Защита от OOM через забивание кэша.

## Range + AES-256-GCM

1. Клиент шлёт `Range: bytes=a-b`
2. `stream_service.get_track_size` возвращает **plaintext** size
3. Блоки расшифровываются on-the-fly (`decryption_service`) при `vfile.is_encrypted`
4. Ответ **206** с корректным `Content-Range`

Ключи vault:
- `ENCRYPTION_RECOVERY_KEY` (primary)
- `ENCRYPTION_FALLBACK_KEYS` (legacy tracks)

См. [[music.env]] · [[Архитектура]]

---

## Auth для `<audio>`

HTML5 `<audio>` не шлёт Authorization. Same-origin cookie-сессия принимается backend для основного URL. Для клиентов без cookie:
1. SPA вызывает `POST /api/stream/token` → short-lived JWT
2. `audio.src = /api/stream/{id}?token=...`
3. query-путь принимает только `scope=stream`; session JWT в URL запрещён

См. [[API Stream]] · [[ADR-004 Cookie Auth CSRF]]
