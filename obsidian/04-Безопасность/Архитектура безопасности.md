# Архитектура безопасности

#tmusic #security

Политика: **Zero-Trust** к входящим запросам. Internet-facing deployment.

Источники: `SECURITY.md`, `backend/app/core/security.py`, `main.py` middleware, `.sec_audit/`.

Связано: [[Аудит 2026-09]] · [[Устранение уязвимостей]] · [[API Auth]]

---

## 1. Brute-force & Rate limiting

| Механизм | Параметр |
|----------|----------|
| Sliding-window per IP | `API_RATE_LIMIT_PER_MIN` (default 120) |
| Auth endpoints | `AUTH_RATE_LIMIT_PER_MIN` (default 10) на `/api/auth/login` |
| Account lockout | `MAX_FAILED_LOGIN_ATTEMPTS=5`, `LOCKOUT_MINUTES=15` |
| Timing attack | `hmac.compare_digest` + dummy-bcrypt для несуществующего логина |
| Аудит | лог `tmusic.auth` без паролей |

---

## 2. Аутентификация и JWT

| Требование | Реализация |
|------------|------------|
| Hash | **только bcrypt**; unsalted SHA-256 отклонён |
| Login | только `POST /api/auth/login` (PIN удалён) |
| Password change | `POST /api/auth/change-password`, min 8 символов |
| JWT | PyJWT, алгоритм whitelist **HS256**, claim `jti` |
| Revocation | таблица `revoked_tokens` + logout |
| token_version | bump при смене пароля |
| Secrets | `music.env` (не в git) |
| Cookie | HttpOnly, SameSite=Lax; `Secure` при `COOKIE_SECURE=true` |
| CSRF | double-submit cookie + `X-CSRF-Token` |
| Stream token | 10 мин, scope=`stream` |
| Bootstrap | `ADMIN_PASSWORD_HASH` → `ensure_admin_bootstrap` |

---

## 3. SSRF (cover proxy)

- Async DNS-резолв (thread pool, не блокирует event loop)
- Блок: RFC1918, loopback, link-local, CGNAT, `169.254.169.254` (cloud metadata)
- Только `http`/`https`
- Cover-эндпоинт **требует auth**
- Timeouts: `COVER_HTTP_TIMEOUT_SEC`, `COVER_HTTP_CONNECT_TIMEOUT_SEC`

---

## 4. Path traversal & Stored XSS

- SPA: `resolve()` + `is_relative_to(FRONTEND_DIST)` (закрыт C-1)
- Cover cache paths: `Path.resolve()` + `is_relative_to(cache_root)`
- Magic bytes image formats; **SVG запрещён**
- Upload limit 10 МБ

## 5. Security headers

| Header | Значение |
|--------|----------|
| X-Content-Type-Options | nosniff |
| X-Frame-Options | DENY |
| Referrer-Policy | strict-origin-when-cross-origin |
| Permissions-Policy | camera/mic/geo/… = () |
| Content-Security-Policy | default-src 'self'; script-src 'self' (**без unsafe-inline**); object-src 'none'; base-uri 'self'; frame-ancestors 'none' |
| Strict-Transport-Security | при `COOKIE_SECURE=true` |

## 6. Telegram-ключи

- At-rest: Fernet от `sha256(SESSION_SECRET)`
- Расшифровка: только in-memory при start
- Self-heal plaintext → encrypted
- CLI: `scripts/secure_tg_accounts.py`

---

## 7. VFS import boundary

- SQL dump принимается только через admin multipart upload с `admin.backups.manage` и CSRF.
- Файл сохраняется под UUID в `data/vfs_imports/`, ограничен 256 МБ и TTL 1 час.
- Dump не исполняется как SQL; parser извлекает только allowlist `folders`, `folder_closures`, `vfiles`.
- `COPY FROM PROGRAM`, бинарный формат и повреждённый UTF-8 отклоняются.
- Preview не возвращает SQL, credentials, `account_map`, session strings или API hashes.
- Импорт использует skip-конфликт, одну DB-транзакцию и rebuild closure table.
- Аудит фиксирует actor, import id и counts, но не содержимое backup.

Подробнее: [[Импорт VFS из SQL]].

---

## 8. Инфраструктура

- Docker: user `tmusic`, HEALTHCHECK, `no-new-privileges`, `cap_drop: ALL`
- `requirements.txt` зафиксирован (pins)
- `DATABASE_URL` обязателен — fail-fast без неявных кредов
- RAM-cache байтовый лимит (DoS memory)
- `REQUIRE_AUTH=false` допустим **только** при `ENVIRONMENT=development` (иначе RuntimeError)
- OpenAPI `/docs` только при `DEBUG=true`

---

## 9. Клиентская безопасность

- React-экранирование, без `dangerouslySetInnerHTML`
- JWT не в localStorage (cookie HttpOnly)
- CSP script-src без inline
