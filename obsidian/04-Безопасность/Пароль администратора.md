# Пароль администратора — фиксированное значение

#tmusic #security #auth #config #testing #admin

Связано: [[music.env]] · [[Архитектура безопасности]] · [[Чеклист безопасности]] · [[00-Главная]]

---

## Решение владельца (2026-10-02)

**Пароль админа всегда `123`.**

`music.env` → `ADMIN_PASSWORD_HASH` — единственный источник истины для этого
пароля. Логин: `admin`.

Это осознанный выбор для личной домашней установки, а не рекомендация по
безопасности. Публичный доступ к панели с паролем из трёх цифр небезопасен:
см. [[Чеклист безопасности]].

---

## Что запрещено

1. **Тесты не вправе переписывать `ADMIN_PASSWORD_HASH`.** Раньше прогон мог
   затереть эту строку, и пароль панели менялся молча.
2. **Тесты не вправе менять `app_settings.admin_bootstrap_hash`** — это зеркало
   применённого хэша в БД.
3. **Тесты не вправе писать в строку `admin` живой БД.** Это и была реальная
   причина блокировки: `test_api.py` и `test_hardening.py` вызывали
   `_provision_admin()`, который коммитил собственный пароль поверх
   `admin`. Прогон `pytest` оставлял панель незалогиниваемой. Теперь эти
   тесты работают через `_AdminPasswordSandbox`, который восстанавливает
   исходный хэш в `finally`.
4. **Хэш не меняется при каждом тестовом прогоне.** Он генерируется один раз.

> Тесты `backend/tests` идут против **настоящей** БД (`DATABASE_URL` из
> `music.env`), а не против отдельной тестовой. Отсюда пункт 3.

## Реализация запрета

### `backend/tests/password_guard.py`

| Функция | Роль |
|---|---|
| `snapshot_admin_hash_line()` | Снимок строки `ADMIN_PASSWORD_HASH` до теста |
| `assert_admin_hash_intact(expected)` | Падение, если строка изменилась или пропала |
| `check_env_unchanged(before)` | Хук teardown: сравнивает снимок с диском |
| `PasswordMutationError` | Исключение с текстом, называющим решение владельца |

Файл `music.env` **не отслеживается git** (`.gitignore`), поэтому страховка
сделана в коде, а не в VCS: единственная точка правды — сам файл на диске.

### `backend/tests/conftest.py`

```python
@pytest.fixture(autouse=True)
def protect_admin_password():
    before = snapshot_admin_hash_line()
    yield
    check_env_unchanged(before)              # строка в music.env
    assert_db_admin_password_intact()       # строка admin в живой БД
```

`autouse=True` — фикстура активна для **каждого** теста в `backend/tests`.
Попытка изменить хэш валит прогон с внятным сообщением, а не проходит тихо.

`assert_db_admin_password_intact()` проверяет пароль через
`verify_password('123', <строка из БД>)`. Сам хэш при этом нигде не хранится.
Если БД недоступна — `pytest.skip`, а не ложное падение.

### `scripts/restore_admin_password.py`

Восстанавливает пароль и синхронизирует `admin_bootstrap_hash` (иначе
`ensure_admin_bootstrap` счтёт хэш «неприменённым» и применит его снова при
следующем старте). Идемпотентен: если пароль уже верный — ничего не меняет.

```powershell
python scripts/restore_admin_password.py
# music.env declares a hash: True
# Password did not match — reset from music.env, sessions revoked.
# VERIFY: '123' accepted = True; account active = True
```

Вызывается автоматически из сообщения об ошибке, если прогон всё же сломал
строку `admin`.

### `backend/app/services/bootstrap.py`

Поведение изменено, чтобы фиксированный пароль действительно держался:

| Ситуация | Поведение |
|---|---|
| Аккаунта `admin` нет | Создаётся с хэшем из `music.env` (provisioning) |
| Аккаунт есть, хэш ещё не привязан (`admin_bootstrap_hash` пуст) | Привязывается один раз |
| Аккаунт есть, хэш уже привязан | **Ничего не меняется** |
| Аккаунт есть, хэш в env отличается от привязанного | Пишется warning, **не применяется** |
| Аккаунт неактивен | Реактивируется, пароль не трогается |

Раньше изменённый env-хэш считался «сознательной ротацией» и перезаписывал
пароль, отзывая сессии. Теперь это невозможно: ротация — только через панель
или `scripts/init_admin.py`.

## Проверки

1. `backend/tests/test_password_guard.py` — 14 тестов: файл существует, схема
   хэша поддерживается, guard ловит изменение и удаление строки, guard также
   накрывает строку `admin` в БД, сообщения называют решение владельца и путь
   восстановления, скрипт восстановления существует, **и ни один тест-модуль
   не пишет пароль в реальную строку `admin` вне песочницы**.
2. `test_api.py::test_auth_password_flow_and_change` — после смены пароля
   тестом логин владельца на `123` всё ещё работает (проверяется прямо).
3. `test_audit_fixes.py::test_bootstrap_does_not_reapply_changed_env_hash` —
   изменённый env-хэш игнорируется, `token_version` не растёт.
4. `test_audit_fixes.py::test_bootstrap_binds_env_hash_once_when_account_never_had_one`
   — первая привязка применяется.
5. `test_argon2_jwt_migration.py::test_argon2_bootstrap_applies_once_and_never_reverts`
   — то же на настоящей БД.
6. Полный прогон: **417 passed, 2 skipped**. После прогона
   `verify_password('123', <строка admin>)` → `True`.
7. `ruff` по изменённым файлам — чисто.

## Как проверить, что всё в порядке

```powershell
python scripts/restore_admin_password.py
# VERIFY: '123' accepted = True; account active = True
```

## Важно

- Значение хэша **не хранится** в репозитории, в Obsidian и в логах.
- Проверка факта «пароль = 123» делается сравнением через
  `security.verify_password('123', <значение из music.env>)`, а не хранением
  хэша в тестах.
- Восстановление/смена: `python scripts/init_admin.py` (интерактивно, через
  `getpass`) — но менять пароль можно только по явному решению владельца.
