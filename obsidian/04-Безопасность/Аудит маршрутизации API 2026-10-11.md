## Область

Все файлы маршрутизации `backend/app/api/` (17 роутеров, 117 зарегистрированных эндпоинтов) плюс связанные
контракты: `api/dependencies.py`, `main.py` (middleware и include_router), `core/body_limits.py`,
`core/rate_limiter.py`, `schemas/`, `services/subsonic_auth.py`, `services/auth_service.py`,
`services/cover_cache_service.py`. Чтение и анализ, код не изменялся (кроме уточняющего
комментария во фронтенде — см. конец).

Проверялось: наличие auth-dependency, валидация/санитайзинг входных параметров, массовое
присвоение, лимиты запросов, раскрытие внутренней информации в ответах об ошибках.

## Проверено и признано корректным

**Аутентификация.** Глобальной auth-dependency нет — каждый эндпоинт объявляет её явно.
Без зависимости остаются только оправданные: `/api/auth/login`, `/api/auth/csrf`,
`/api/auth/logout`, `/api/system/config` (site_title + maintenance_mode),
`POST /api/system/client-logs`, `/api/share/{token}`, `/api/share/{token}/stream` (публичные
шары, токен 144 бита, TTL), `/rest/*` (собственная Subsonic-аутентификация в `_handle`,
принудительная для всех методов). `REQUIRE_AUTH=false` вне `ENVIRONMENT=development`
отвергается на старте (`core/config.py:244`).

**Контроль доступа (IDOR).** Плейлисты, позиции, история, избранное, шары — всё
фильтруется по `user.id` (`playlist_service.*`, `playback_service.*`, `share_router.py:122,138`).
Админские операции — за `get_admin_user` / `get_backup_admin` / `get_catalog_user`.

**Валидация.** Path-параметры типизированы (`int`), списки ограничены
(`PlaylistMirror.file_ids` ≤5000, `ArtistBatchUpdate.artist_ids` ≤500, `FileMove.file_ids` ≤1000),
строки — `min_length`/`max_length`/`pattern` (`CreateUser.role` по `^(admin\|editor\|user)$`,
`ChangePasswordRequest` 8..128). `kind` проверяется по `VALID_KINDS`
(`music_library_service.py:288,328`). Пароль — 1..1024 на входе, 8..128 на смене.

**Массовое присвоение.** Не найдено: `PATCH`-обработчики присваивают только поименованные поля
(`admin_router.py:415–427`, `admin_vfs_router.py:472–554`, `admin_catalog_router.py:90–101`),
`PUT /api/admin/settings` пишет только ключи из белого списка `ALLOWED_SETTING_KEYS`
(`admin_router.py:327–335`); `model_dump` используется лишь для аудита.

**Rate limiting.** Глобально: 120/мин на IP для `/api/*`, 10/мин на `/api/auth/login`,
600/мин на `/rest/*`, 30/мин на IP для client-logs, 10/60 с на пользователя для
`POST /transcode`, ограничение числа SSE-подписок (429). Тело запроса ограничено
(`MAX_JSON_BODY_BYTES` 1 МБ, 11 МБ на загрузки обложек/аватара, 257 МБ на импорт VFS).

**Раскрытие информации.** Глобальный обработчик `Exception` (`main.py:179–193`) пишет
трейс в лог и отдаёт `{"detail": "Internal server error."}`. Логин возвращает одинаковые
сообщения при блокировке по IP и по аккаунту, счётчик остаётся на сервере. Access-лог
пишет `request.url.path` без query — `?token=` в логи не попадает.

**Прочее.** SSRF: `cover_cache_service.fetch_and_cache` сам проверяет `is_safe_host`
(DNS + запрет private/loopback/link-local/169.254.169.254). Path traversal:
`_safe_resolve_in` (basename + resolve + is_relative_to), имена бэкапов — по regex с
проверкой `is_relative_to` и `is_symlink`. ZIP-дамп читается выбранным членом в фиксированный
путь, `extractall` не используется, распаковка ограничена 1 ГБ. Subsonic: панельный пароль
в query не принимается, только выделенный токен через `hmac.compare_digest`, с lockout.
CSRF: double-submit middleware на все мутирующие cookie-запросы.
