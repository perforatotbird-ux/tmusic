## 1. Сценарий 1: Проверка безопасности (Промпты №1–№4)

### 1.1. OWASP Top 10 (Промпт №1)
- **A01: Broken Access Control:** Все 110 маршрутов API разделены по ролевым зависимостям (`get_admin_user`, `get_catalog_user`, `get_current_user`, `get_stream_user`). Path traversal в SPA/VFS блокируется проверками `resolve()` + `is_relative_to()`. BOLA/IDOR предотвращён проверками владения плейлистами и треками.
- **A02: Cryptographic Failures:** Пароли хешируются через **Argon2id** (v=19, 64 МБ RAM, t=3, p=1). Сессионные токены JWT снабжены обязательными полями `uid`, `jti`, `tv` (token_version) и HMAC-SHA256 подписью. Зарезервированные поля защищены от перезаписи при создании.
- **A03: Injection:** Все запросы SQLAlchemy параметризованы. Запуск `ffmpeg` и `ffprobe` выполняется через список аргументов без `shell=True`. Вызов `REINDEX DATABASE` в `admin_service.py` использует имя базы из системной функции `current_database()`.
- **A04: Insecure Design:** Внедрён `BodySizeLimitMiddleware` (1 МБ JSON, 11 МБ обложки, 257 МБ дамп VFS). Вычисления KDF Argon2id ограничены семафором `PASSWORD_HASH_CONCURRENCY=2`.
- **A05: Security Misconfiguration:** Заголовки безопасности (CSP без unsafe-inline, nosniff, DENY, HSTS). Для локальной сети действует режим `CORS_ALLOW_LAN` (см. замечание ниже).
- **A06: Vulnerable Components:** Зависимости зафиксированы в `requirements.txt`.
- **A07: Identification & Auth Failures:** Защита от timing-атак через `timing_equalizer_hash`. Ограничение частоты запросов к `/api/auth/login` (10 req/min). Токены мгновенно отзываются при смене пароля.
- **A08: Software & Data Integrity:** Валидация Pydantic v2, отсутствие небезопасной десериализации.
- **A09: Logging & Monitoring:** Чувствительные данные (`token`, `password`, `authorization`) маскируются строкой `[redacted]` в логах.
- **A10: SSRF:** Проверка URL через `is_safe_host()` в `cover_cache_service.py` блокирует доступ к loopback, RFC 1918 и cloud metadata IP.

### 1.2. Периметр API (Промпт №2)
- Проверено 110 эндпоинтов: 56 эндпоинтов требуют прав администратора, 45 — авторизации пользователя, 6 — специализированные публичные/служебные.
- Риск Mass Assignment отсутствует (строгие Pydantic schemas).
- Утечки информации в ошибках исключены: глобальный обработчик `unhandled_exception_handler` возвращает нейтральный `{"detail": "Internal server error."}` со статусом 500.

### 1.3. Утечки секретов (Промпт №3)
- В репозитории Git секреты отсутствуют. Файлы `music.env` и `postgres_password` находятся в `.gitignore`.
- Шаблон `music.env.example` содержит только плейсхолдеры.

### 1.4. Аутентификация и авторизация (Промпт №4)
- **CORS LAN Policy [Medium]:** При `CORS_ALLOW_LAN=True` регулярное выражение разрешает запросы из локальных подсетей с `allow_credentials=True`. Рекомендуется отключать на публичных серверах.

## 2. Сценарий 2: Поиск багов и асинхронность (Промпты №5–№8)

### 2.1. Граничные условия и null safety (Промпт №5)
- Деление на ноль в аналитике и воспроизведении защищено условиями `if track_duration and track_duration > 0`.
- Отрицательные и нечисловые значения длительности (`NaN`, `Infinity`) безопасным образом нормализуются.

### 2.2. Асинхронность и Event Loop (Промпт №6)
- **Замечание [Medium -> Устранено]:** В `transcoding_service.py` и `ffmpeg_transcoder.py` синхронный запуск `subprocess.run(ffprobe)` (получение длительности `get_mp3_duration`), запись временных файлов и MP3-кэша на диск, сохранение кэш-манифеста и сканирование/ротация кэша вынесены в тред-пул через `await asyncio.to_thread(...)`. Блокировка Event Loop FastAPI полностью устранена (см. [[Ревью async 2026-10-01#ASYNC-13]]).
- **Фронтенд:** `favoritesStore.js` использует очереди мутаций и эпохи `generation === epoch`, предотвращая состояния гонки.

### 2.3. Логические ошибки (Промпт №7)
- Защита от блокировки системы: невозможно снять права администратора или деактивировать последнего активного администратора.
- Зеркалирование плейлистов защищено блокировкой строки владельца (`with_for_update()`).

### 2.4. Обработка ошибок (Промпт №8)
- Все мутирующие транзакции снабжены обязательным `db.rollback()` при перехвате исключений.
- Блоки `except: pass` проанализированы: все 37 случаев приходятся на штатное удаление временных файлов (`unlink(missing_ok=True)`) и не влияют на бизнес-логику.
