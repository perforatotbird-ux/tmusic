## Критические находки

### C-1. Path Traversal → чтение файлов без auth
- **Файл:** `backend/app/main.py` (`serve_spa`)
- **Баг:** `FRONTEND_DIST / full_path` без `resolve()` / `is_relative_to`
- **PoC:** `curl --path-as-is "http://target:8005/..%2F..%2Fmusic.env"` → секреты в ответе
- **Kill chain:** SECRET_KEY → подделка JWT; SESSION_SECRET → расшифровка TG-сессий; DATABASE_URL → PG; выход на файловую систему хоста

### C-2. Дефолтные учётные данные
- `admin/admin123`, PIN `1234` в миграции
- Unsalted SHA-256 password hashes

### C-3. Компрометация секретов
- `music.env` с реальными ключами был доступен через C-1
- `SECRET_KEY` требовал ротации

---

## Средние / прочие

- Публичный cover-proxy
- CSP `unsafe-inline` в script-src
- Root-пользователь Docker
- python-jose (CVE-2024-33663/33664)
- Rate-limiter реализован, но не wired
- LIKE-escape отсутствовал
- RAM-cache без байтового лимита

---

## Вердикт аудита

Отдельные механизмы уже были сильными (SSRF-фильтр, bcrypt, JWT-revocation, magic-bytes), но **C-1 + хранение секретов в music.env = полная компрометация одним неаутентифицированным GET**.

Статус после remediation: [[Устранение уязвимостей]]
