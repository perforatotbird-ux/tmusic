## 1. Резюме аудита и статус релиза

Проведён полный независимый аудит безопасности кодовой базы T-Music в рамках подготовки к возможному открытию сервиса в публичный интернет. Проверены все компоненты: бэкенд на FastAPI (122 эндпоинта), фронтенд React 19, мобильный клиент Capacitor / Android, шифрование сессий Telegram, стриминговый и транскодирующий пайплайн, а также механизмы защиты от брутфорса и DoS.

### Итоговый вердикт: **BLOCKED**

Публичный доступ в открытый интернет **недопустим** до устранения двух критических блокеров:
1. **SEC-001 (CRITICAL): Фиксированный пароль администратора `123`.** В соответствии с решением владельца от 2026-10-02 для домашней сети установлен пароль `123`. При выводе приложения в публичный интернет этот пароль подбирается первой же попыткой словарной атаки, передавая злоумышленнику полный контроль над системой, бэкапами и базой данных.
2. **SEC-002 (HIGH): Неаутентифицированный DoS через блокировку учётной записи в Subsonic API.** Маршрут `/rest/*` вызывает `_record_failure(db, user)` при ошибке авторизации. Лимит запросов к `/rest/*` составляет 600 req/min без блокировки IP. Злоумышленник может отправить 5 быстрых GET-запросов `/rest/ping.view?u=admin&p=bad` и заблокировать вход администратора в веб-панель на 15 минут. Повторение запросов каждые 14 минут делает блокировку перманентной.

## 3. Детальный разбор уязвимостей

### SEC-001: Дефолтный пароль администратора `admin:123`
- **Файл:** `backend/app/services/bootstrap.py`, `music.env`, `backend/tests/password_guard.py`.
- **Суть проблемы:** Значение `ADMIN_PASSWORD_HASH` в `music.env` задаёт хэш пароля `123`. В `conftest.py` работает фикстура `protect_admin_password`, защищающая этот пароль от перезаписи тестами. Для домашней сети это осознанное решение владельца (см. [[Пароль администратора]]). Однако в модели публичного интернета панель администратора раскрывает критические функции: VFS импорт из SQL дампа, вакуумирование и реиндексация БД, создание пользователей и просмотр логов.
- **Действия:**
  - *Вариант 1 (Сетевая изоляция):* Оставить пароль `123` для локального использования, но на уровне внешнего реверс-прокси (Nginx / Traefik / VPN) закрыть маршруты `/api/admin/*` и `POST /api/auth/login` для всех внешних IP, разрешив доступ только из доверенной подсети/VPN.
  - *Вариант 2 (Ротация в продакшене):* При развёртывании на публичном сервере задать криптографически стойкий случайный пароль через `python scripts/init_admin.py` и очистить переменную `ADMIN_PASSWORD_HASH`.

### SEC-002: Неаутентифицированный DoS через Subsonic API [УСТРАНЕНО]
- **Файл:** `backend/app/services/subsonic_auth.py`, `backend/app/api/subsonic_router.py`.
- **Суть проблемы:** Ранее вызов `/rest/*` при ошибке авторизации вызывал `_record_failure(db, user)`, инкрементируя `app_users.failed_login_attempts`. При 5 ошибках аккаунт блокировался на 15 минут в базе данных.
- **Решение:** Ошибки аутентификации Subsonic переведены на учёт по IP клиента (`limiter.record_failure(f"subsonic_{client_ip}")`). Строка пользователя в БД не модифицируется (`failed_login_attempts` и `locked_until` не изменяются). Добавлен регрессионный тест `test_subsonic_failure_does_not_lock_web_user` в `backend/tests/test_subsonic.py`.

### SEC-003: Исторические секреты в Git
- **Суть проблемы:** В коммите `d09674c839b636e1a3a069fdde6119cfb101b878` содержался старый пароль PostgreSQL.
- **Исправление:** Интерактивная смена пароля в рабочей базе данных через `ALTER USER postgres WITH PASSWORD ...`, обновление `.secrets/postgres_password` и чистка истории через `git-filter-repo` при согласовании с владельцем.

### SEC-004: Безопасность мобильного клиента [УСТРАНЕНО]
- **Файлы:** `mobile/capacitor.config.ts`, `mobile/android/app/build.gradle`, `mobile/android/app/src/main/AndroidManifest.xml`, `scripts/build_android_apk.ps1`.
- **Суть проблемы:** Ранее были включены флаги `cleartext: true`, `android:usesCleartextTraffic="true"` и `allowNavigation: ['*']`.
- **Решение:** В `capacitor.config.ts` удалён wildcard `['*']`, навигация ограничена доменом сервера (в debug — приватными LAN-диапазонами). В `build.gradle` настроен `manifestPlaceholders = [usesCleartextTraffic: "false"]` для release-сборок (в debug — `"true"` для локальной сети). В `AndroidManifest.xml` значение заменено на плейсхолдер `${usesCleartextTraffic}`. Сборка `processReleaseManifest` подтверждает генерацию релизного манифеста со строгим `usesCleartextTraffic="false"`.

## 4. Проверенные механизмы защиты (Defense-in-Depth)

В ходе аудита подтверждена высокая надёжность ключевых защитных подсистем:
1. **Argon2id KDF:** Современные параметры памяти и раундов, параллелизм ограничен семафором, вычисления KDF изолированы в отдельных потоках. Исключены тайминг-атаки по логину благодаря `timing_equalizer_hash`.
2. **PyJWT и отзыв токенов:** Проверка типов `HS256`, обязательные клеймы (`sub`, `exp`, `iat`, `jti`, `uid`, `tv`), серверная таблица отзыва токенов с LRU-кэшем.
3. **Fail-Closed CSRF:** Проверка двойной куки обязательна для всех мутирующих запросов с cookie-аутентификацией.
4. **Защита от SSRF:** `_PinnedResolver` валидирует IP-адреса, блокирует приватные подсети, loopback и адреса метаданных облаков (`169.254.169.254`). SVG строго запрещён, изображения валидируются по magic bytes.
5. **Path Traversal:** Защита подтверждена в SPA routing (`is_relative_to`), кэше обложек и транскодере (`safe_src_ext`).
