## H-1 — блокировка аккаунта анонимом и перечисление логинов

- Новый модуль `backend/app/core/login_device.py`: после успешного входа браузер получает cookie `login_device` (HttpOnly, SameSite=Strict, путь `/api/auth`, срок `LOGIN_DEVICE_TRUST_DAYS`, по умолчанию 30 дней). Подпись HMAC от `SESSION_SECRET`, привязка к `user.id` и `token_version` — смена пароля или «выйти везде» обнуляет все доверенные устройства.
- `AuthService.authenticate_by_password`: доверенное устройство не попадает под общую блокировку аккаунта и блокировку по IP; его ошибки считаются отдельно (`device:<id>`) и блокируют только это устройство.
- Недоверенные клиенты — прежние лимиты по IP и аккаунту.
- Любой отказ (нет пользователя, неактивен, заблокирован, неверный пароль) — одинаковый ответ `Invalid credentials.` и один Argon2id-verify → ни текст, ни время не выдают существование аккаунта.

## M-1 — загрузка 257 МБ до аутентификации

- `BodySizeLimitMiddleware` теперь самый внутренний middleware (TrustedHost, CORS, rate limit, CSRF срабатывают раньше).
- Пути с лимитом > 32 МБ (`/api/admin/vfs/import/preview|upload`) проходят проверку сессии и права `admin.backups.manage` **до чтения тела**; аноним получает 401/403 сразу.
- Не более 2 одновременных больших загрузок (иначе 429).

## M-2 — X-Forwarded-For

- `app/utils/client_ip.py`: IP клиента = N-я запись справа (`TRUSTED_PROXY_HOPS`, по умолчанию 1), а не левая (её задаёт сам клиент). Опционально `TRUSTED_PROXY_IPS` — заголовки прокси принимаются только от этих адресов.
- Access-логи пишут реальный IP клиента.

## M-3 — UDP discovery

- По умолчанию **выключен** (`DISCOVERY_ENABLED=false`), порт `DISCOVERY_PORT`. Приложение Android находит сервер и через HTTP-пробу `/health`.
- Отвечает только частным/loopback/link-local адресам, лимит 10 ответов в минуту на источник, кэш LAN-адресов 60 с, логирование пакетов — DEBUG.
- В `docker-compose.yml` публикация `8211/udp` закомментирована.

## M-4 — Android `AndroidMediaBridge`

- Каждый метод моста проверяет origin текущей страницы: разрешены только встроенный лаунчер `https://localhost` и origin сохранённого сервера.
- `connectToServer` / `saveServerUrl` принимают только `http(s)` с хостом и без user-info.
- Сборка Android в среде исправлений не проверялась — нужна проверка в Android Studio.

## M-5 — Subsonic

- `SUBSONIC_ENABLED=false` теперь реально отключает `/rest/*` (404).
- Убран dummy-Argon2 только для неизвестных пользователей (тайминг-оракул): все ветки делают одинаковую дешёвую проверку.
- Веб-блокировка `locked_until` больше не отключает Subsonic-клиентов (отдельный токен, свой лимит по IP).
- `getUser`: `adminRole`/`settingsRole` по реальным правам.

## M-6 — небезопасные значения по умолчанию

- `COOKIE_SECURE` по умолчанию **авто**: Secure-cookie и HSTS включаются, если запрос пришёл по HTTPS (в том числе через доверенный прокси). Явное `true/false` по-прежнему главнее.
- При `ENVIRONMENT=production` на старте предупреждения в лог: `TRUSTED_HOSTS=["*"]`, `COOKIE_SECURE=false`, `CORS_ALLOW_LAN=true`, `TRUST_PROXY_HEADERS` без `TRUSTED_PROXY_IPS`.
- `music.env.example` дополнен новыми настройками.

## Баги

- **B-1:** аватар не сохранялся — `set_avatar`/`reset_avatar` меняли отсоединённый объект из `user_cache`. Теперь правится строка из сессии (`get_attached_user`) + сброс кэша.
- **B-2:** тесты падали без локального `music.env` (CI / чистый checkout). Защитник пароля теперь пропускает проверку, если файла с `ADMIN_PASSWORD_HASH` нет, но падает, если тест его создал.
- **B-3:** устаревшие тесты — удаление артиста (папка остаётся, пока на неё ссылается файл в корзине), тест расшифровки пропускается без мастер-ключей, regex фронтенд-теста обновлён под текущий текст.

## Что изменилось для владельца

- Хотите UDP-автопоиск в LAN — `DISCOVERY_ENABLED=true` в `music.env` и раскомментировать порт в compose.
- Сообщение о блокировке аккаунта больше не показывается — всегда «Invalid credentials.».
- За reverse proxy с несколькими уровнями — выставить `TRUSTED_PROXY_HOPS`.
