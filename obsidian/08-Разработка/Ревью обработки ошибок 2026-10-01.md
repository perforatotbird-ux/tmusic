## Этап 1 — инвентаризация

Ветка `argon2idmigration`, включая предыдущие незакоммиченные исправления. Код приложения не изменяется. Собраны 404 совпадения except/catch/commit/rollback в backend/app, frontend/src, Android Kotlin и scripts; число совпадений не равно числу дефектов. Изучаются propagation, публичные сообщения, critical mutations и rollback. Платёжных интеграций в backend/app/frontend/src не обнаружено; вместо них проверяются auth, playlists, VFS, admin и backup restore.

Уже установлено: get_db делает rollback и re-raise; global exception handler выдаёт generic 500, а traceback остаётся серверным; restore использует --single-transaction/--exit-on-error; mirror/import включают data+audit в один commit. Общий catch в cleanup/fallback сам по себе не считается багом.

Кандидаты требуют подтверждения: Fernet failure классифицируется как plaintext и повторно sealed; logout failure скрыт; purge после revocation commit может оставить DB session failed; create+add playlist состоит из двух mutations; Last.fm JSON error считается успехом; UI mutation ошибки только console/rollback без сообщения; detail-object становится [object Object]; streaming exception оборачивается HTTPException после начала response.

## Что работает корректно

- Конкретные exception types используются в security (JWT/Argon2id), admin restore, validation и subprocess timeout/file-not-found. Global Exception допустим как last-resort boundary; в get_db/mirror catch Exception не проглатывает ошибку, а rollback + raise сохраняет propagation.
- get_db закрывает session и откатывает незакоммиченные изменения; import/mirror rollback paths и data+audit single commit присутствуют. HTTP network failure после commit всё равно означает неизвестный результат, не гарантированный rollback.
- Restore backup имеет --single-transaction и --exit-on-error. Это подтверждённая конфигурация команды, не выполненный живой PostgreSQL restore.
- Global 500 generic; backup restore RuntimeError sanitised; SQL-import unexpected failure sanitised. Отдельное исключение — tree-import в ERR-03.
- Пустые catches в autoplay unlock, optional localStorage, cache fallback, best-effort metadata и cleanup не перечисляются как дефекты только из-за формы catch. Ошибки optional external интеграций не обязаны откатывать playback history, но не должны логироваться как успешная доставка.
- Платежей в проверенном application code не обнаружено; payment rollback неприменим к этому проекту.

### Ограничения и эксплуатация

Если ciphertext уже был double-wrapped прежним кодом, эти правки предотвращают дальнейшее повреждение, но **не восстанавливают рабочие данные автоматически**. Нужна координированная проверка резервной копии/ключей; не удалять credentials и не менять SESSION_SECRET наугад. Runtime изолирует некорректный TG account, CLI aborts без commit всей пачки. Format detection сохраняет explicit legacy compatibility, а не является универсальным валидатором любой произвольной строки.

Logout marker хранит только boolean в tab-scoped sessionStorage, не JWT; при недоступном storage действует in-memory warning. До успешного retry checkAuth/login заблокированы, но это не серверный revoke само по себе. При потерянном mutation reply результат может быть неизвестен: UI предлагает обновить/проверить список, не слепую повторную запись. Favorite optimistic rollback не доказывает откат уже committed server mutation; refresh сверяет фактическое состояние.

Live PostgreSQL/Telegram/Last.fm, реальные encrypted downloads/ffmpeg, proxy/Android device playback и живой restore не запускались. Никаких production secrets или DB volumes не изменялось. Все 9 локальных исправлений закрыты тестами; live integration/deployment остаются отдельными действиями.
