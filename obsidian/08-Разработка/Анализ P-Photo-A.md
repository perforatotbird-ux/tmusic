# Анализ иерархии P:\Photo\A

> Только чтение. Ни один скрипт не удаляет, не перемещает и не переименовывает файлы в `P:\Photo\A`.

## Расположение результатов

Папка `K:\Test\tmusic\photo_a_analysis\`:

| Файл | Назначение |
|------|-----------|
| `analyze_photo_a.ps1` | первичный обход уровней 1–2 |
| `analyze_photo_a_d4.ps1` | обход до глубины 4, пишет `photo_a_depth4.tsv` |
| `summarize_d4.ps1` | сводка по TSV (счётчики по глубине) |
| `build_report.py` | строит SQLite, CSV и HTML из TSV |
| `photo_a_depth4.tsv` | сырые данные: глубина, относительный путь, число подпапок, файлов |
| `photo_a.sqlite` | таблицы `hierarchy`, `models`, `studios` |
| `photo_a_hierarchy.csv` | та же иерархия в CSV |
| `photo_a_report.html` | отчёт с фильтром по строкам |

## Результаты

- Верхний уровень: 48 папок.
- Всего папок до глубины 4: 5433 строки в `hierarchy`.
- Студии (по правилу `Studio\Model\Set`): `Art modeling studio`, `A little agency`, `Agency Modeling`.
- Модели без студии: папки верхнего уровня, в которых подпапок нет (модель) или есть (модель с сетами).
- Глубина дерева: 4. На уровне 4 — 71 папка, все без подпапок.

## Ограничения

- Классификация `set` / `subset` выведена по позиции в дереве, а не по содержимому файлов.
- Числовые подпапки (`01`, `02`...) считаются сетами, но это не проверено.
- Одинаковые названия сетов у разных моделей не сведены в один справочник.
- Доменные суффиксы в именах (`alena-model.com`, `Alisa model.com`) не нормализованы.

## Как перегенерировать

```powershell
pwsh -NoProfile -File K:\Test\tmusic\photo_a_analysis\analyze_photo_a_d4.ps1
python K:\Test\tmusic\photo_a_analysis\build_report.py
```

Первый скрипт пишет TSV во временную папку; его нужно скопировать в `photo_a_analysis\` перед `build_report.py`.
