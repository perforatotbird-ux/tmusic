## O(n²) и выше

### 1. `frontend/src/components/AdminVfsImport.jsx:219-238` — `findAncestorIds`
- **Текущая:** O(depth × P × F). Внешний `while (currId)` поднимается по дереву, на каждом шаге
  перебирает **все** записи `Object.entries(childrenMap)` (P) и делает `.some(f => f.id === currId)`
  по папкам каждого родителя (F). Для глубокого дерева ≈ **O(n²)**.
- **Целевая:** O(depth).
- **План:** один раз построить `parentByChild: Map<childId, parentId>` из `childrenMap`
  (перебрать все пары один раз, O(n)); `findAncestorIds` идёт вверх по Map. Индекс перестраивать
  в том же месте, где обновляется `childrenMap`.

### 2. `backend/app/services/vfs_import_service.py:1983-1997` и `:2181-2195` — `get_staged_depth` + `sorted(..., key=get_staged_depth)`
- **Текущая:** O(n · depth) на вычисление ключей + O(n log n) сортировки → **O(n²)** при глубоком дереве.
- **Целевая:** O(n log n).
- **План:** предвычислить глубину мемоизированным DFS (как уже сделано для `snapshot.depth_by_id`,
  который используется на `:586` и `:937` за O(1)), затем `sorted(all_folder_ids, key=depth_by_id.get)`.
  Кэш `depth` строить один раз на снапшот.

Сторы/сервисы используют поверхностные копии (`{...obj}`, `new Set(...)`, `new Map(...)`) — корректно.

## Конкатенация строк — проблем нет

встречается только в `core/logging_config.py:119,121` и `scripts/extract_logs.py:126,128` — это
формирование **одного** заголовка записи (O(1), не цикл по данным). Замены не требуется.

## Сортировка — алгоритмы подходящие

- `playerStore.js:224-233` `buildShuffleOrder` — **Fisher-Yates**, O(n) (корректно).
- `utils/lrc.js:42`, `utils/cachedBrowse.js:122,124`, `services/offlineStorageService.js:286` —
  сортировки с явными компараторами (O(n log n)).
- `vfs_import_service.py:586,937` — `sorted(key=depth_by_id.get)` (O(n log n), ключ O(1)).
- Единственное исключение — п.2 выше (ключ вычисляется на лету).

## Приоритет исправления

1. **П.2** (backend): O(n²) на импорте большого дерева — самый высокий.
2. **П.1** (frontend): O(n²) в `findAncestorIds` при большом дереве VFS.
3. **П.4–6**: O(n) → O(1), микрооптимизации (заметны только на больших очередях/деревьях).
