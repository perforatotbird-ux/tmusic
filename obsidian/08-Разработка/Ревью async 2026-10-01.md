# Ревью async 2026-10-01

#tmusic #dev #async #review

## Область

Ветка argon2idmigration с локальными Argon2id и edge-case fixes. Async/await, Promise, callbacks, asyncio tasks, worker pools и транзакции. Первоначально проведено ревью; по следующему запросу ASYNC-01…ASYNC-12 исправлены и покрыты regression tests. CORS/рабочая БД не менялись.

## Этап 1 — обзор

- Собран inventory await/Promise/callback/create_task в frontend/src, public/sw.js, mobile/www, backend/app и scripts.
- Проверены request try/catch, store updates после await, cache single-flight/invalidation, cover shared Future, ffmpeg cancellation, worker lifecycle и VFS transaction/audit boundaries.
- Кандидаты: stale seek после смены трека; auth/favorites ответы после logout/reset; cache bust во время pending fetch; pagination append после смены фильтра; shared Future cancellation; ffmpeg child cleanup; worker exception outside handler; sync I/O внутри async routes; импорт commit до audit.
- Последовательный await не объявляется багом автоматически: ordered media chunks, retry/failover и paginated discovery с неизвестной длиной нельзя безусловно заменить на Promise.all.
- Динамические воспроизведения выполнены на синтетических данных; без Telegram/внешних providers/рабочих secrets.

## Этап 2 — подтверждённые сценарии

- Original JS в VM + настоящий Zustand: stale resume после onTrackChanged; late /me после logout; late favorites load после reset; failure rollback одного favorite отменяет успешный toggle другого.
- Original cache module: bustCache не удаляет pending fetch; последующий memoize получает старый pending и снова кеширует старый результат.
- Извлечённые оригинальные handlers: loadMore добавляет старую страницу к новому фильтру; FolderBrowser mirror после всех deletes и failed adds оставляет remote playlist пустым, ошибки проглочены.
- Shared cover Future: отмена одного await отменяет обоих waiters; producer получает InvalidStateError и unretrieved task exception.
- Active _transcode_track: timeout и CancelledError не вызывают child kill/wait (FakeProcess, реальные ffmpeg/Telegram не запускались).
- Worker metadata DB failure: task завершён вне job-level exception handler, _started остаётся True, queue unfinished count=1.
- Original async lyrics route + mocked sync provider: heartbeat задержан на 0.080 секунды при time.sleep(0.08), подтверждает блокировку event loop. Реальный provider использует urlopen, backup route — subprocess.run.
- Original SQL import + SQLite + сбой _audit: после rollback handler импортированный файл остаётся committed, state=completed. Это разрыв атомарности import/audit, не неработающий rollback до commit.
- Original import polling callback: late completed status старого импорта после нового pollRef.current отменяет новый timer и пишет старый progress.

## Promise, циклы и callbacks — без ложных находок

- Отсутствие буквального .catch не означает missing error handling: await внутри try/catch или возвращённый Promise с handling у caller корректны. Самостоятельную воспроизведённую JS network Promise rejection без обработки не зарегистрировано; ASYNC-03/04 — ошибки asyncio tasks, ASYNC-11 — проглатывание ошибок, а не отсутствие catch.
- MusicLibrary.jsx:258–260: два независимых cover manifests (custom=0/1) можно выполнять Promise.all; низкоприоритетная оптимизация, не correctness bug.
- Service worker trimCoverCache/trimShellCache удаляют independent keys последовательно: возможна bounded parallel deletion; quota/error policy сохранить. install/activate уже используют Promise.all.
- FolderBrowser mirror требует batch transaction, не Promise.all delete/add. Stream chunks, Telegram mirrors/retry, redirects и пагинация с неизвестным концом имеют зависимости; массовая параллелизация нарушает порядок, лимиты или семантику.
- Выраженного callback hell не обнаружено. playerStore autoplay retry вложен, но сам по себе не подтверждает дефект; рефакторить отдельно от lifecycle/epoch fixes.
- get_db на обычной ошибке делает rollback, finally close закрывает активную транзакцию и при cancellation. Импорт корректно rollback до service commit; ASYNC-12 только о последующей audit phase. CreateUser IntegrityError rollback из предыдущих фиксов сохранён.
- Реальные pg_restore/pg_dump, SMTP/Telegram/provider APIs, credentials не использовались. Никаких deployment/DB cleanup/истории Git изменений.

## Исправления — этап 1

- ASYNC-05…09: session/query generations, per-ID favorite rollback и очередь toggle, serialized login/logout, invalidation pending cache и guarded resume/pagination.
- ASYNC-01…04: sync provider/backup handlers работают в threadpool; scheduler создаёт DB session внутри worker и ждёт активный backup при shutdown (до timeout pg_dump). Имена backup содержат микросекунды. ffmpeg kill + drain/reap перед очисткой source, shared cover Future защищён shield; producers отменяются/собираются при shutdown. Весь acquired job охвачен exception handler, task_done всегда в finally.
- Это промежуточный этап: постоянные регрессионные тесты ещё не выполнены. CORS не менялся.

## Исправления — этап 2

- ASYNC-11: POST /api/playlists/mirror принимает name + уникальные положительные file_ids (до 5000), валидирует все доступные файлы до удаления, находит/создаёт принадлежащий пользователю playlist и заменяет items в одной транзакции. Lock владельца сериализует параллельное создание mirror; lock playlist согласован с add/remove/reorder/delete и Subsonic mutations. ### Ограничения эксплуатации

Graceful stop backup scheduler ждёт активный worker до завершения pg_dump (его существующий timeout — 30 минут). Сессия БД создаётся и закрывается в том же worker. После HTTP network failure результат mirror может быть неизвестен: нужно обновить список, а не считать его гарантированно откатившимся. Контролируемый server-side failure до commit гарантирует rollback. Перед deployment нужна disposable PostgreSQL integration/concurrency проверка.
