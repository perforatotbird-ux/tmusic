# Ревью граничных значений 2026-10-01

#tmusic #dev #review #bugs

## Область и статус

Ветка `argon2idmigration`, включая локальную незакоммиченную миграцию Argon2id. Анализ null/undefined, индексации, деления, пустых строк и числового parsing. Зависимости node_modules, build outputs и секретные runtime-файлы не входят в ревью собственного кода. После исходного анализа владелец запросил исправления: они реализуются локально ниже; CORS не меняется.

## Метод и охват

- Составлен inventory tracked исходников, добавленные локальные исходники учтены отдельно.
- AST проход по Python: динамические делители и константные индексы; текстовый поиск JS/JSX/TS/Kotlin и встроенного JS в mobile/www.
- Проверены guards на encrypted header/block_size, queue next/prev, API-поля, optional DB joins, volume parseFloat, UI scrub duration.
- Выявлены кандидаты: playNext с неправильным queueIndex; usernames/playlist names из пробелов; LRCLIB null item до фильтра; Retry-After HTTP-date -> NaN; empty archive indexing; nonfinite listening history.
- Выполнены локальные воспроизведения с SQLite, FastAPI TestClient, VM оригинального JS с изолированными зависимостями и mocked provider. Реальные PostgreSQL/Telegram/Last.fm/LRCLIB не вызываются.
- Inventory: 160 файлов форматов Python, JS/JSX/TS, Kotlin/Java, HTML и PS1/BAT, включая tests/audit utilities и четыре добавленных исходника текущей ветки. Все 105 Python-файлов разобраны AST без syntax errors. Это автоматизированный проход по всем исходникам и ручная проверка кандидатов, не построчное ручное ревью каждого файла.

## Исходные проверки и оговорки

- Node VM исполняет исходный playerStore с настоящим Zustand и заглушками transport/timers/native API; воспроизведены три варианта BUG-01. Это не full-browser E2E.
- Для BUG-05 выполнен request() исходного api/client с mocked HTTP 429 и HTTP-date; зафиксирован NaN delay.
- BUG-02/03: оригинальные schemas/services/router, in-memory SQLite; пустые записи и normalized unique collision подтверждены.
- BUG-04: mocked LRCLIB search с null; реальный provider не опрашивался.
- BUG-06: временный пустой ZIP, оригинальная _read_zip; IndexError подтверждён.
- BUG-07: FastAPI TestClient, in-memory SQLite, original playback/admin routers; providers mocked. POST/GET history=200 (nonfinite поле превращается в null), admin analytics=500, DB contains inf. Не путать это с 500 непосредственно в POST history: первоначальный helper-only тест JSONResponse не отражал современную FastAPI serialization и был уточнён HTTP-проверкой.
- Достижимое деление на ноль в проверенных рабочих путях не подтверждено: encryption block_size нормализуется parse_header, scrub max защищён, Python offset helpers получают валидированный block size. Искусственный direct call с block_size=0 не регистрируется как runtime bug без caller.
- parseFloat storedVolume имеет Number.isFinite fallback; range input обычно отдаёт числовое значение. Не регистрируется ложная находка только по наличию parseFloat.
- Проверка не меняла код, CORS, БД рабочего стенда или secrets. Изменены только заметки Obsidian. На момент исходного анализа исправления оставались открытыми; последующий статус — ниже.

## Исправления — этап 1

- BUG-01: вставка/перемещение выполняются относительно ID текущего трека; currentTrack не меняется, queueIndex сохраняет соответствие. Play next для текущего трека — no-op.
- BUG-02/03: trim до schema length validation, нормализованный unique lookup, rollback при гонке create. Service layer отвергает пустые/слишком длинные playlist names; Subsonic create/update валидирует имя и возвращает protocol error.
- BUG-04: non-dict элементы отфильтрованы до сортировки; lyrics/string metadata и duration валидируются, nonfinite duration превращается в None.
- BUG-05: Retry-After integer seconds/HTTP-date, finite check, fallback 60 секунд, UI wait cap 300 секунд; запрос по-прежнему не повторяется автоматически.
- BUG-06: пустые/directory-only ZIP дают понятную ошибку и exit 1, выбирается первый недиректорный файл.
- BUG-07: history durations только конечные 0..86400 секунд, защита service layer; старые некорректные значения санитайзятся при чтении и исключаются из суммы до aggregation. Сами записи БД не переписываются автоматически.
- Код исправлен локально; итоговые проверки — ниже. CORS и рабочая БД не изменены.

## Исправления — этап 2: регрессии

- Добавлен frontend/tests/edge-cases.test.cjs и npm test (Node builtin test runner, без новых зависимостей). Тесты исполняют оригинальные Zustand actions/API client в VM с изолированными browser/network side effects; Retry-After helper импортируется напрямую.
- Frontend: 9 тестов успешно. Подтверждён следующий scheduled track при shuffle, включая перемещение history/upcoming, текущий последний, пустую очередь и date/seconds parsing.
- Backend выбранный изолированный набор: **212 passed**, 5 прежних warnings; frontend Node: **9 passed**; production build: **успешно**, 1666 modules. Production/PostgreSQL deployment не выполняется.

## Ограничения

Это review собственного кода, не доказательство отсутствия всех багов. Условия с некорректным upstream response или повреждённым архивом фиксируются отдельно от штатных сценариев. Для деления на ноль нужна достижимость через реальный caller, а не вызов helper с неподдерживаемыми аргументами.
