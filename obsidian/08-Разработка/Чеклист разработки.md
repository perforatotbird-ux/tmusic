# Чеклист разработки

#tmusic #dev #процесс

---

## Перед тем как писать код

1. Открыть [[Карта репозитория]] — найти слой (api / service / repo / tg / ui)
2. Не нарушать [[ADR-001 No God Objects]]
3. Секреты и SQL **не** заводить в router/UI
4. Понять, затрагивает ли изменение auth/stream/security → сверить [[Чеклист безопасности]]

---

## Backend change

- [ ] Изменения в правильном слое
- [ ] Pydantic schemas обновлены при смене контракта
- [ ] Индексы/запросы не деградируют (N+1, LIKE без escape)
- [ ] Новые env-ключи — в `config.py` **и** `music.env.example` (без реальных секретов)
- [ ] Нет implicit credentials / hardcoded URL
- [ ] Auth-guards на новых `/api/*` (или явное public-исключение)
- [ ] Rate-limit sensitivity учтён
- [ ] TG-изменения идут через manager helpers (`ensure_encrypted` и пр.)
- [ ] `python -m pytest` в `backend/`
- [ ] `python -m pytest tests/test_vfs_import.py -q` после изменения importer
- [ ] ruff/lint если настроен в среде

---

## Frontend change

- [ ] API вызовы через `src/api/*` (не голый fetch)
- [ ] Cookie/CSRF не ломаются
- [ ] 401 → AuthModal path
- [ ] Player-store не мутирует чужое состояние вне actions
- [ ] Prefetch abort при новой очереди
- [ ] `npm run build` без ошибок
- [ ] PWA / Media Session не сломаны, если трогали player

---

## Security-sensitive change

См. [[Чеклист безопасности]]. Дополнительно:
- [ ] Нет path join без `resolve`/`is_relative_to`
- [ ] Нет нового open-proxy
- [ ] CSP не ослабляется
- [ ] Upload validation сохранена
- [ ] VFS SQL import: admin permission, CSRF, UTF-8/size/TTL, allowlist parser и rollback
- [ ] VFS SQL import: credentials/raw SQL не попадают в preview, logs и audit
- [ ] Нет логов паролей/токенов/секретов
- [ ] Regression-тест traversal / auth

---

## Release / deploy

- [ ] Frontend rebuild → `dist/` (или docker build)
- [ ] `music.env` заполнен; example синхронизирован по ключам
- [ ] Unit-тесты зелёные; integration при живой БД
- [ ] `secure_tg_accounts.py --check`
- [ ] Smoke: login → library → play → range seek
- [ ] Логи startup: DB OK, admin bootstrap OK, TG clients started

---

## Что не делать

- Коммитить `music.env`, реальные хэши, session strings
- Возвращать PIN / дефолтные креды
- Класть JWT в localStorage или long-lived JWT в query
- Игнорировать `DATABASE_URL` fail-fast
- Добавлять зависимости без pin в `requirements.txt`
- Писать god-service «и UI, и TG, и кэш»
