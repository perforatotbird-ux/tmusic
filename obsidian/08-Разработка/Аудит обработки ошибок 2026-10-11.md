# Аудит обработки ошибок 2026-10-11

#tmusic #code-quality #error-handling #audit

## Область и метод

Проверена обработка ошибок во всём коде: `backend/app` (try/except, HTTPException, глобальный
handler, транзакции) и `frontend/src` (try/catch, `.catch()`, ErrorBoundary, сообщения в UI).
Вопросы: (1) конкретные vs общие исключения; (2) «проглатывание» в catch; (3) передача наверх;
(4) понятность и неразглашение внутренних деталей; (5) откат критических операций.
Метод: паттерн-поиск + ручная проверка кандидатов. Результаты отсортированы по критичности.

## Краткие ответы

1. **Конкретные исключения** — используются широко (`VfsImportError`, `IntegrityError`,
   `FileNotFoundError`, `TimeoutExpired`, `ValueError`, `PermissionError`, `InvalidTokenError`,
   `TGCredentialError`, `VerificationError`…). Голых `except:` нет. Общий `except Exception`
   применяется в основном для best-effort/cleanup — см. L1/L2.
2. **Проглатывание** — есть, но почти всё — best-effort (кэш, обогащение, discovery, cleanup) —
   L1/L2. В критическом пути импорта — корректно (rollback + код ошибки).
3. **Передача наверх** — корректна: глобальный handler + ErrorBoundary + `ApiError`.
4. **Сообщения** — в основном безопасны; одна утечка внутренних деталей в UI — M1.
5. **Откат** — реализован: `get_db`, явные `rollback()` в многошаговых операциях, оптимистичный
   откат избранного во фронтенде.

## Проверено и корректно

**Конкретные исключения и откат критического пути.** `services/vfs_import_service.py:2391-2409` —
образцово: `except VfsImportError` → `db.rollback()` → контролируемый текст → `raise`; и
`except Exception` → `db.rollback()` → **обобщённое сообщение с кодом-ссылкой** (`uuid`), полный
трейс в лог, `raise VfsImportError(message, 500) from exc`. `services/admin_service.py:357-369` —
`FileNotFoundError`/`TimeoutExpired` ловятся конкретно.

**Откат транзакций.** `core/database.py:26-35 get_db` — `rollback()` при исключении + `close()`;
явные откаты в многошаговых операциях: `api/admin_router.py:424` (IntegrityError при гонке
создания пользователя), `services/playlist_service.py:71,94`, `services/vfs_import_service.py:998,
1092,1097,2392,2400`, `repositories/search_repository.py:38`.

**Передача наверх.** Backend: `main.py:179-193` — последний обработчик логирует трейс и отдаёт
`{"detail": "Internal server error."}` (без деталей). Frontend: `ErrorBoundary` ловит ошибки
рендера; `api/client.js:39-46` превращает сетевые сбои в `ApiError`; ошибки шлются в
`/api/system/client-logs` через `utils/logger.js`.

**Сообщения без утечек.** Логин — одинаковые тексты при блокировке по IP и по аккаунту, счётчик
серверный (`services/auth_service.py:36-42,101-112`); restore — белый список
`_SAFE_RESTORE_DETAILS` (`api/admin_router.py:313-320`); все `detail=f"..."` содержат только
счётчики/имена типов (`library_router.py:99`, `music_library_service.py:224,289,369,377`).

**Фронтенд-откат данных.** `store/favoritesStore.js:44-80` — оптимистичное изменение с **откатом
по конкретному ID** при ошибке (`update(wasFavorite)`), сериализация через `pending`-map и
epoch-guard. `store/authStore.js:23-27` `mutateSession` — возвращает `result` вызывающему (ошибка
пробрасывается), а `mutationTail` гасит rejection только чтобы не рвать цепочку.
