## Этап 4 — backend исправления

По новому запросу пользователя внесены локальные исправления RES-01/02/03/06. Audio, share, Subsonic stream/download и SSE освобождают read session до сетевого потока; необходимые поля копируются. Telegram startup использует finally для незарегистрированного клиента, включая cancellation. Завершённые transcode jobs ограничены 1000 записями/1 часом, sweep на idle worker каждые 60 секунд; shutdown очищает jobs/очередь. Worker download также закрывает DB до Telegram I/O.

Producer buffering получает общий отдельный бюджет RAM_CACHE_MAX_BYTES: резервируется удвоенный размер plaintext для bytearray и bytes-копии. Oversized/занятый бюджет не мешает streaming, но отключает накопление для кэша; finally освобождает reservation. Хранимый RAM-cache и суммарные in-flight buffers имеют отдельные лимиты по RAM_CACHE_MAX_BYTES (совместно до двух бюджетов, без учёта накладных расходов/сетевых chunks). Проверка полноты plaintext сохранена даже без cache buffer.

Тестирование этого этапа ещё не завершено; исправления не опубликованы. CORS неизменен.

## Этап 5 — frontend исправления

RES-04/05/07/08/09: resume handlers дедуплицированы, recovery/readiness callbacks и retry timers снимаются; generation отсеивает поздние play rejection. API cache ограничен 128 entries и оценкой JSON UTF-16 payload 16 MiB (не точное heap measurement); один expiry timeout удаляет expired entries даже без запросов, invalidation очищает таймер.

SSE больше не создаётся при module load: App управляет им по authenticated/password-change state. Logout/reset закрывает EventSource, callback и notification timers; удаление последнего элемента очереди сохраняет auth-scoped SSE. Root cleanup сохраняет playback snapshot, освобождает audio/queue/watchdog/prefetch, MediaSession/native handlers; новый mount может восстановить snapshot. UI toast/playlist timeouts имеют handles и unmount cleanup, поздний async success не заводит новый таймер после teardown.

Внесён код, regression проверки и browser smoke ещё выполняются; не считать deployment завершённым. CORS неизменен, commit/push не выполнялись.

## Повторная проверка перед push

После восстановления: полный backend прогон — 357 passed, 31 failed; все 31 failure подтверждены как OperationalError/Connection refused к недоступному PostgreSQL. Frontend — 86 passed; production build успешен (тот же JS bundle hash, что после исходного исправления). Browser smoke повторяется отдельно. Публикация ещё не подтверждена; код и Obsidian будут отправлены через подключённый GitHub MCP, поскольку CLI credentials отсутствуют.

Локальная Git-история является mirror: исходники совпадают с удалённой базой по tree SHA, но local/remote commit SHA могут отличаться. Не применять force-push для их согласования. Удалённая ветка argon2idmigration сохраняется: пользователь удалит её сам.

Повторный browser smoke успешен: реальный React StrictMode mount/unmount/remount, очистка audio/watchdog/MediaSession, restore snapshot, logout/relogin с одним SSE. API/EventSource и валидный WAV синтетические; temporary HTML fixture удалена. git diff --check успешен. Текущий этап — публикация в master без переписывания истории.
