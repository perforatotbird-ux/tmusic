# Аудит запросов к базе данных 2026-10-11

#tmusic #database #orm #performance #n+1 #audit

## Область и метод

Проверены `backend/app/models/`, `backend/app/repositories/` и все вызовы ORM в
`backend/app/api/` и `backend/app/services/`. Критерии: N+1 (запросы в циклах), отсутствующие
индексы, `SELECT *`, отсутствие пагинации, повторяющиеся запросы. Метод: чтение моделей/репозиториев
+ паттерн-поиск циклов с запросами внутри.

## Итог

**Слой репозиториев и модели — оптимизированы.** Проблемы сосредоточены в **Subsonic-слое**
(`subsonic_router.py`, совместимость `/rest/*`) и паре админских мест. Основное — **N+1**.

## N+1 (запросы внутри циклов)

| Файл:Строка | Проблема | Влияние | Решение |
|---|---|---|---|
| `api/subsonic_router.py:269-283` | `getIndexes`/`getArtists`: `for a in artists: db.scalar(count(MusicAlbum) …)` — счётчик на каждого артиста | N+1: до N+1 запросов на запрос; плюс **выборка всех артистов без limit** | Один `GROUP BY artist_id` для счётчиков + пагинация |
| `api/subsonic_router.py:383-394` | `getAlbumList`: `for alb in albums: _catalog_artist(db, alb.artist_id)` | N+1 до 500 доп. запросов (`size` ≤ 500) | Предзагрузить артистов одним `IN (...)` / `selectinload` |
| `api/subsonic_router.py:308-320` | `getArtist`: `for alb in albums: db.scalar(count(VFile) …)` | N+1: счётчик треков на альбом | Один `GROUP BY folder_id` |
| `api/subsonic_router.py:125-150` | `_random_song_rows` (getRandomSongs): на трек `select(MusicAlbum)` + `_catalog_artist` | N+1: 2 запроса × до 500 треков | Джойн VFile→MusicAlbum→MusicArtist в одном запросе |
| `api/subsonic_router.py:502-508, 546-550, 575-577, 888` | `getPlaylist`/`getStarred`/shares: per-row `select(MusicAlbum)` / `FileRepository.get_by_id` | N+1 на каждый элемент списка | Батч-выборка по id-списку |
| `api/subsonic_router.py:795` | `getSimilarSongs`: вложенный цикл `for a in artists: _artist_songs(db, a, …)` | N+1 (×число похожих артистов) | Один запрос с `IN (artist_ids)` |
| `api/admin_vfs_router.py:440-450` | Листинг папок: `for folder in folders: db.scalar(count(Folder))` + `db.scalar(count(VFile))` | N+1: 2 запроса на папку | Сгруппированные counts одним запросом |
| `services/vfs_import_service.py:1876-1877` | `for child_fid in imported_children_fids: db.get(Folder, child_fid)` | N+1 (смягчено identity-map при активной сессии) | Загрузить папки одним `IN (...)` |

## `SELECT *` (лишние колонки)

| Файл:Строка | Проблема | Влияние | Решение |
|---|---|---|---|
| `api/subsonic_router.py:92` | `_catalog_artist`: `select(MusicArtist)` — все колонки, включая Text `bio`/`wikipedia_url` | Лишние тяжёлые поля в горячем пути | `load_only(id, display_name)` (или `.options(load_only(...))`) |
| `api/subsonic_router.py:138,157,172,461,508` | `select(MusicAlbum)` — все колонки (вкл. Text `cover_url`) там, где нужны лишь `id/title/artist_id` | Лишний трафик БД→приложение | `load_only(id, title, artist_id, folder_id)` |
| `api/subsonic_router.py:270` | `select(MusicArtist)` в `getIndexes` | То же | `load_only(id, display_name)` |
| `api/admin_vfs_router.py:433` | `select(VFile)` — вся строка, включая тяжёлые `encryption_header`/`account_map`/`note` | Лишние Text/JSON на каждый файл листинга | `load_only(...)` как в `file_repository._TRACK_LIST_COLUMNS` |

## Проверено и корректно

**Индексы — покрыты полностью** (`models/`):
- `vfiles`: `folder_id`/`is_trash` (композит), `mime_type`, `is_trash+mime_type`, `name`.
- `folders`: `name`, `parent_id+is_trash`; `folder_closures`: `ancestor_id`, `descendant_id`.
- `music_artists`: `folder_id` (unique), `kind`, `parent_id`, `display_name`, `search_name`, `custom_image_key`.
- `music_albums`: `folder_id` (unique), `artist_id`, `title`, `artist_id+year`, `custom_image_key`.
- `playback_positions` (unique `user_id+file_id`), `listening_history` (`user_id+started_at`, `user_id+file_id`),
  `user_favorites` (unique + `user_id+created_at`), `playlists` (`user_id+name`),
  `playlist_items` (unique + `playlist_id+position`), `share_links` (`token` unique, `user_id+created_at`),
  `revoked_tokens` (`jti` unique, `expires_at`), `admin_audit_events` (`created_at` и др.).

**Репозитории — оптимизированы:**
- `repositories/file_repository.py` — `load_only(*_TRACK_LIST_COLUMNS)` (без `SELECT *`), `limit`/`offset`.
- `repositories/artist_repository.py` — `list_artists` берёт `album_count`/`parent_name`/`children_count`
  **коррелированными подзапросами за один round-trip** (комментарий в коде); `get_by_id` —
  `selectinload(MusicArtist.albums)` (без N+1); `ancestor_ids` с `max_depth`.
- `repositories/album_repository.py` — `load_only(*_ALBUM_CARD_COLUMNS)`, `limit`/`offset`.
- `repositories/search_repository.py` — trigram-индексы (`pg_trgm`).

**Прочие вызовы:** `stream_router.py:266,268` и `vfs_router.py:132,155,157` передают `limit` в
`list_tracks_*`; основная библиотека (`music_library_service`) строит карточки через репозитории
(подзапросы), без N+1.

## Статус исправления (2026-10-11)

Исправлены N+1, `SELECT *` и пагинация в Subsonic-слое и админских местах.

| Категория | Файл:Строка | Правка |
|---|---|---|
| N+1 | `api/subsonic_router.py:269-283` | `getIndexes`/`getArtists`: один `GROUP BY artist_id` вместо count на артиста |
| N+1 | `api/subsonic_router.py:383-394` | `getAlbumList`: имена артистов одним `IN (...)` (было N запросов) |
| N+1 | `api/subsonic_router.py:308-320` | `getArtist`: один `GROUP BY folder_id` для `songCount` |
| N+1 | `api/subsonic_router.py:125-150` | `_random_song_rows`: один JOIN VFile→Album→Artist (было 2 запроса/трек) |
| N+1 | `api/admin_vfs_router.py:439-457` | листинг папок: один `GROUP BY` на каждый счётчик (было 2 запроса/папку) |
| N+1 | `services/vfs_import_service.py:1876` | children + albums одним `IN (...)` (было 2 запроса/ребёнка) |
| `SELECT *` | `api/subsonic_router.py:91` | `_catalog_artist` → `load_only(id, display_name)` |
| `SELECT *` | `api/admin_vfs_router.py:412,433` | `select(VFile)` → `load_only(id, name, folder_id, size, mime_type)` |
| Пагинация | `api/subsonic_router.py:97` | `_album_songs`: `list_tracks_recursive(..., limit=1000)` |

**Оставлено осознанно:** `getIndexes`/`getArtists` по-прежнему возвращают всех артистов — это
семантика Subsonic-метода (счётчики уже не N+1); `select(MusicAlbum)` в `getAlbumList` грузит
карточные колонки (тяжёлых Text, кроме `cover_url`, нет — при желании добавить `load_only`).
Пункт «повторяющиеся запросы» закрыт батч-выборками выше (в рамках одного запроса дублирования нет).
