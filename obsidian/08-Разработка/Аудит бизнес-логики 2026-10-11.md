## Область и метод

Проверена бизнес-логика `backend/app` и `frontend/src` по 5 критериям: покрытие веток `if/else`,
условия завершения циклов, операторы сравнения (`==` vs `===`, `>` vs `>=`), область видимости
переменных, возврат значения на всех путях. Метод: паттерн-поиск + ручное чтение кандидатов.

## Находки (по критичности)

### Средняя

| Файл:Строка | Проблема | Влияние | Решение |
|---|---|---|---|
| `backend/app/services/vfs_import_service.py:1775` (и `:1970`, `:2162`) | Обход цепочки родителей (`parent_id`) **без защиты от цикла**. `:1775` (`preserve_parent_path`) и `get_staged_depth` (`:1970`, `:2162`) идут вверх по `parent_id`, полагаясь только на `is_backup_root`/отсутствие родителя. При циклической иерархии в источнике (`A.parent=B`, `B.parent=A`, оба не backup-root) — **бесконечный цикл**. Остальные обходы в этом же файле защищены (`:476` `current not in paths`, `:918` `current_id not in visited`), т.е. это несогласованность | Загруженный SQL-дамп с циклом в `folders.parent_id` (повреждённый/подготовленный) вешает обработку импорта: запрос не завершается, воркер занят (DoS-подобно) | Добавить `visited`-множество и `break` при повторе |

Пример исправления (`:1772-1791`):

```python
if preserve_parent_path:
    for fid in leaf_selected_folders:
        curr = fid
        seen: set[int] = set()
        while True:
            if curr in seen:          # cyclic parent chain in a corrupt dump
                break
            seen.add(curr)
            row = conn.execute("SELECT id, name, parent_id FROM folders WHERE id = ?", (curr,)).fetchone()
            if not row or not row["parent_id"]:
                break
            pid = row["parent_id"]
            p_row = conn.execute("SELECT id, name, parent_id FROM folders WHERE id = ?", (pid,)).fetchone()
            if not p_row:
                break
            ...
            curr = pid
```

И `get_staged_depth` (`:1967-1973`, `:2159-2165`):

```python
def get_staged_depth(fid: int) -> int:
    depth = 0
    seen: set[int] = set()
    cur = staged_folders.get(fid)
    while cur and cur["parent_id"] in staged_folders:
        pid = cur["parent_id"]
        if pid in seen:               # cycle guard
            break
        seen.add(pid)
        depth += 1
        cur = staged_folders.get(pid)
    return depth
```

## Проверено и корректно

**Покрытие `if/else`.** Диспетчер Subsonic завершается явным дефолтом
(`subsonic_router.py:927` `Method '{method}' is not implemented`). Аутентификация Subsonic
(`services/subsonic_auth.py:99-137`) возвращает на всех ветках (нет username / unknown / inactive /
locked / оба режима / успех / провал). `music_library_service` валидирует `kind` по `VALID_KINDS`
и бросает на неизвестном. Права — `api/dependencies.py:34-46` покрывают все роли + legacy `admin`.

**Завершение циклов.** Помимо находки выше — все циклы ограничены:
`body_limits.py:40` (break на `not more_body`), `downloader.py:230` (`segment_remaining -= chunk_len`,
`raise` при провале всех зеркал), `decryption_service.py:187` (`del buffer[:enc_bs]`),
`stream_service.py:205,370,381` (break на пустом чтении / `remaining -=`),
`ram_cache_service.py:91` и `disk_cache.py:124` (pop каждый шаг),
`vfs_router.py:106` (`guard < 32`), `admin_vfs_router.py:123,517` (`not in visited`),
`AdminCatalog.jsx:157,387` (`for(;;)` с break по `items.length < PAGE || all.length >= MAX_TOTAL`),
`api/stream.js:26` (`attempt < MAX_POLLS`), `lrc.js:52` (бинарь `lo<=hi`),
`cache.js:14` (pop каждый шаг), `AdminPanel.jsx:51`/`AdminVfsImport.jsx:33` (`i < u.length - 1`).

**Операторы сравнения.** Loose-equality во фронтенде встречается **только** как `== null` / `!= null`
(`playerStore.js:159,254,272,650,657,1279`, `offlineStore.js:127,150,169`, `lrc.js:48`,
`offlineStorageService.js:163,202,231,305,344,415,667`, `MusicLibraryPlayer.jsx:207,208,357,369`,
`api/vfs.js:11`, `api/playlists.js:13`, `utils/cachedBrowse.js:81`, `logger.js:46`) — это идиоматичная
проверка `null || undefined`, корректно. Прочих `==`/`!=` нет. В Python `is`/`is not` используется
только с `None`/синглтонами (misuse `is "str"`/`is 0` не найдено). Границы включительно/исключительно
проверены в rate-limiter (`>= max_requests` — блок на (max+1)-м, `>= max_attempts` — блок на N-й
неудаче) — корректно.

**Область видимости.** Во фронтенде `var` не используется вовсе (`let`/`const`); замыкания в
`useEffect` очищаются через возвращаемую функцию (`App.jsx`, `SharePage.jsx` — `active`-флаг +
`clearTimeout`). В Python области стандартные, теней глобального состояния не найдено.

**Возврат на всех путях.** Проверены `utils/msg_ids.py:16-59` (`parse_msg_ids` — return на всех
ветках), `utils/cover.js:16-38` (`firstTruthy`/`resolveCoverUrl`), `utils/lrc.js:47-62`,
`api/client.js:23-37` (`httpError` — тернарная цепочка с дефолтом), `playerStore.js:156-172`
(`sanitizeQueueTrack` — null либо объект), `stream_service.parse_range_header` — return на всех путях.
