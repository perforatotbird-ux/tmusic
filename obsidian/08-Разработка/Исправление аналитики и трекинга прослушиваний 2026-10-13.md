# Исправление аналитики и трекинга прослушиваний (2026-10-13)

#tmusic #backend #frontend #analytics #playback

## Контекст проблемы

В панели администратора раздел «Аналитика» создавал впечатление полной неработоспособности: после прослушивания треков в плеере новые воспроизведения не отображались в статистике.

### Корневые причины

1. **Потеря длительности и дублирование в `listening_history`**:
   - `frontend/src/services/playbackProgress.js` при старте трека вызывал `markHistoryStart` с `duration_played_sec = 0.0, completed = False`.
   - При паузе, ручном переключении трека или закрытии страницы накопленное время воспроизведения не сбрасывалось на бэкенд (обновлялась только `playback_positions`). В результате в базе данных накапливались сотни записей с `duration_played_sec == 0`.
   - При доигрывании трека до конца вызывался `onEnded`, отправлявший повторный `addHistory` без ссылки на первоначальную запись, что приводило к созданию дублирующей строки на одно воспроизведение.
2. **Слепая зона в UI админки**:
   - Вкладка «Аналитика» отображала только «Топ-20 треков за 30 дней» (где трек появлялся только после преодоления порога в 4 прослушивания) и топ пользователей.
   - Одиночные или свежие прослушивания новых треков нигде не отображались.
   - Отсутствовала лента недавних событий прослушивания (`recent events`).
   - Кнопка «Обновить» в шапке админки не перезапрашивала аналитику при открытой вкладке.
3. **Безопасность и совместимость JSON**:
   - Наличие исторических строк с нечисловыми или бесконечными значениями (`Infinity`) могло приводить к ошибкам сериализации JSON (500 Internal Server Error) при выдаче недавних событий.

## Внесённые изменения

### Backend

1. **`backend/app/schemas/playback.py`**:
   - `HistoryCreate`: добавлено опциональное поле `history_id: Optional[int] = None`.
2. **`backend/app/repositories/playback_repository.py`**:
   - Добавлен метод `get_history(db, history_id, user_id)` для безопасной выборки существующей записи истории текущего пользователя.
3. **`backend/app/services/playback_service.py`**:
   - В `add_history` поддержано обновление существующей записи на месте: если передан валидный `history_id`, сервис выполняет обновление `duration_played_sec = max(existing, new)`, `track_duration_sec` и `completed = True` вместо вставки дубликата.
4. **`backend/app/api/playback_router.py`**:
   - `POST /api/playback/history`: принимает `history_id`, передаёт в сервис. Скроблинг в Last.fm вызывается при завершении или достижении порога, а `update_now_playing` — только на старте (когда `history_id` отсутствует).
5. **`backend/app/api/admin_router.py`**:
   - Эндпоинт `GET /api/admin/analytics`:
     - Добавлена выборка `recent`: последние 30 событий прослушивания по всем пользователям с полями `id`, `user_id`, `username`, `file_id`, `track_name`, `started_at`, `duration_played_sec`, `track_duration_sec`, `completed`.
     - Санитизация длительностей `_sanitize_duration` с фильтрацией `NaN`/`Infinity` для предотвращения сбоев сериализации JSON (read-only совместимость с историческими данными).

### Frontend

1. **`frontend/src/services/playbackProgress.js`**:
   - Сохранение `historyId` из ответа бэкенда на стартовое событие `addHistory`.
   - Аккумуляция точного времени прослушивания (`state.lastCurrentTime`).
   - Метод `flushHistoryUpdate(completed)` для фиксации накопленного времени.
   - Сброс прогресса вызывается:
     - при переключении трека (`onTrackChanged`);
     - при паузе (`onPause`);
     - при завершении трека (`onEnded` с `completed: true`);
     - при закрытии/выгрузке вкладки через `pagehide` и `beforeunload`.
2. **`frontend/src/App.jsx`**:
   - Аудиоэлемент связан со слушателем `onPause={handlePause}` для фиксации прогресса прослушивания.
3. **`frontend/src/components/AdminPanel.jsx`**:
   - Добавлен переключатель временного окна аналитики: 7 / 30 / 90 дней.
   - Добавлен индикатор загрузки (`analyticsLoading`) и кнопка ручного обновления блока аналитики.
   - В шапке кнопка «Обновить» (`handleRefresh`) синхронизирована с активной вкладкой аналитики.
   - Добавлен блок **«Свежие прослушивания (последние события)»** со списком последних 30 треков, именем пользователя, длительностью воспроизведения и бейджем завершения.
   - Добавлен блок **«Активность по дням»** на основе данных `daily`.
