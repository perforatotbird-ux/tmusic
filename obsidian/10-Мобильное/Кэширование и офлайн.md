## Обзор

В мобильное приложение (Capacitor 8 Android WebView / Web SPA) внедрена полнофункциональная система управления данными и кэшем в стиле **Telegram**:

1. **Гибкие настройки хранилища:**
   - **Максимальный размер кэша (LRU):** 500 МБ, 1 ГБ, 2 ГБ, 5 ГБ, 10 ГБ или без лимита. При достижении порога автоматически удаляются треки, к которым дольше всего не обращались.
   - **Время жизни кэша (TTL):** 3 дня, 1 неделя, 1 месяц, навсегда. Автоматическая очистка устаревших файлов в фоне при запуске приложения и смене настроек.
   - **Выбор типов данных для кэширования:** аудиофайлы, обложки альбомов, тексты песен (LRC), каталожные данные.
   - **Автокэширование при прослушивании:** автоматическое бесшовное сохранение трека в локальное хранилище во время воспроизведения (как в Telegram).

2. **Полноценный офлайн-режим (Offline Audio Playback):**
   - Возможность воспроизведения сохранённых треков без интернет-соединения (в самолёте, метро, за городом).
   - Воспроизведение через нативные Blob URL (`URL.createObjectURL(blob)`), не требующее обращения к серверу.
   - Автоматический возврат к потоку при наличии сети и индикация ошибки при попытке включить незакешированный трек в офлайне.

3. **Сквозная визуальная индикация кэшированных треков:**
   - Все сохранённые на устройстве треки выделяются стильным зелёным бейджем `✓ Кэш`.
   - Бейджи отображаются во всех интерфейсах: в каталоге релизов, в Windows-проводнике папок, в недавних треках и плейлистах, в очереди воспроизведения, на панели мини-плеера и на полноэкранном экране плеера.
   - В каталоге добавлен виртуальный раздел **«В кэше»** с возможностью запустить воспроизведение всей закешированной музыки в 1 тап.

4. **Раздел «В кэше» — навигация Артист → Альбом → Трек:**
   - Раздел показывает **карточки Артистов** (а не одну заглушку), собранные из метаданных закешированных треков.
   - Тап по артисту → его кэшированные альбомы; тап по альбому → треклист с кнопкой Play; тап по ▶ на карточке альбома — воспроизведение альбома; «Слушать всё» на артисте — все его закешированные треки.
   - Обложки берутся из `coverUrl`, сохранённого вместе с треком.

## Архитектура клиентского хранилища

### IndexedDB (`tmusic_offline_cache`, версия 1)

Использует нативную базу данных браузера / Android WebView:

| Хранилище (ObjectStore) | Ключ (`keyPath`) | Индексы | Назначение |
|-------------------------|------------------|---------|------------|
| `tracks` | `fileId` (number) | `lastAccessedAt`, `cachedAt`, `size` | Бинарные аудио-Blob, метаданные трека, размер и таймстемпы обращений |
| `covers` | `url` (string) | `lastAccessedAt`, `cachedAt`, `size` | Бинарные Blob изображений обложек |
| `metadata` | `key` (string) | `type`, `lastAccessedAt` | Тексты песен LRC, JSON списков каталога |
| `settings` | `id` (string) | — | Конфигурация кэша пользователя (зеркалируется в `localStorage`) |

### Интеграция с Android OS (Native Storage Bridge)

В файл `mobile/android/app/src/main/java/app/tmusic/mobile/AndroidMediaBridge.kt` добавлен метод:
- `@JavascriptInterface fun getDeviceStorageInfo(): String`: использует `android.os.StatFs` для получения общего объёма памяти устройства, доступного свободного места и размера локального кэша приложения.
- JS-обёртка `frontend/src/services/nativeBridge.js` транслирует эти данные в интерфейс диалога Telegram-стиля.

## Компоненты и логика

1. `frontend/src/services/offlineStorageService.js`:
   - Ядро работы с IndexedDB: сохранение, загрузка Blob, расчёт детальной статистики (аудио / обложки / метаданные).
   - Фоновый загрузчик `downloadTrackForOffline(track)`.
   - Алгоритм фоновой очистки по TTL (`runEviction`): удаление записей старше `cacheTtlDays`.
   - Алгоритм LRU вытеснения по размеру (`checkAndEvictSize`): последовательное удаление наименее востребованных треков при превышении `maxCacheSizeMb`.

2. `frontend/src/store/offlineStore.js`:
   - Реактивный Zustand-стор, синхронизирующий список закешированных треков `cachedTrackIds` (in-memory Set для O(1) проверок), статус загрузок `cachingTrackIds`, статус сети (`isOffline`) и события `tmusic:cache-updated`.

3. `frontend/src/components/StorageSettingsModal.jsx`:
   - Telegram-style окно управления памятью:
     - Цветная сегментированная полоса занятого пространства (Аудио, Обложки, Метаданные, Свободно на устройстве).
     - Кнопка «Очистить кэш» с выбором категорий (чекбоксы).
     - Селекторы срока хранения и максимального размера кэша.
     - Тумблеры кэшируемых данных и автокэширования.
     - Вкладка «Музыка в кэше» с поиском, возможностью послушать офлайн и удалить конкретный трек.

4. `frontend/src/store/playerStore.js`:
   - В методе `startAudio` проверяется наличие трека в кэше.
   - Если трек в кэше: загружается Blob из IndexedDB, создаётся Blob URL (`URL.createObjectURL`), освобождается предыдущий URL (`URL.revokeObjectURL`) во избежание утечек памяти.
   - Если включено автокэширование: после старта воспроизведения трек автоматически скачивается в IndexedDB в фоне.
   - В упреждающей предзагрузке (`precacheNextTracks`) пропускаются треки, уже сохранённые локально.

## Раздел «В кэше»: дерево Артист → Альбом → Трек

Кэш на устройстве хранит **плоские** строки: `artist`, `album`, `coverUrl` лежат
как обычные строки в каждом треке (`getAllCachedTracks`). Дерево восстанавливается
на клиенте — каталожный API не вызывается, альбом существует в разделе, пока
хотя бы один его трек лежит на устройстве.

### `frontend/src/utils/cachedBrowse.js` (новый модуль)

| Экспорт | Назначение |
|---------|-----------|
| `cachedToTrack(row)` | Приводит строку кэша к виду, который ждёт `playerStore.playQueue` |
| `groupCachedTracks(rows)` | Собирает `Артист → Альбом → Трек`; бакеты ключуются без учёта регистра, отображаемое имя — первое увиденное |
| `cachedArtistCard(group)` | Карточка артиста в форме каталожной (`display_name`, `album_count`, `cover_url`) |
| `cachedAlbumCard(album)` | Карточка альбома + `cached_tracks` для локального треклиста |
| `isCachedArtistCardId(id)` | Отличает кэш-карточку (`tmusic:cached:*`) от каталожного id |

Пустые метаданные попадают в бакеты **«Без исполнителя»** / **«Без альбома»**, и
для них обложка намеренно не наследуется от одного случайного трека — иначе
несколько несвязанных треков показывали бы одну и ту же картинку.

### Правка воспроизведения (баг)

Раздел «В кэше» собирал элементы очереди как `id: c.file_id`, но строки
IndexedDB содержат `id`/`fileId` — поля `file_id` там нет. `id` получался
`undefined`, и `startAudio()` выходил на `if (!audio || fileId == null) return`:
**Play не делал ничего, без ошибки и без уведомления.**

Теперь преобразование идёт через `cachedToTrack`, которая читает `id ?? fileId`.

### Интеграция

- `SECTIONS` в `MusicLibrary.jsx`: `В кэше` переведён в `isAlbum: false` —
  раздел рендерит сетку карточек артистов.
- `openArtist`: для `tmusic:cached:*` группа открывается из памяти, без запроса
  к каталогу (иначе 404).
- `handlePlayAlbum` / `openAlbum`: ветка `is_cached_album` играет локальный
  треклист и открывает `AlbumDetail` без `folder_id`.
- `handlePlayAllArtist`: для кэш-артиста играет все треки группы.
- `AlbumDetail` принимает проп `cachedTracks`; при его наличии запрос
  `getFolderTracks` не выполняется.
- Кнопка «Изменить фото» у кэш-артиста скрыта: писать обложку некуда.

## Тестирование и верификация

1. **Модульные тесты:** `frontend/tests/offline-storage.test.cjs`:
   - Проверка дефолтных настроек Telegram-стиля.
   - Проверка сохранения и частичного обновления конфигурации.
   - Проверка TTL-вытеснения (удаление устаревших и сохранение свежих записей).
   - Проверка режима `cacheTtlDays=0` (хранить вечно).
   - Проверка LRU-вытеснения по размеру при превышении квоты.
   - Проверка выборочной и полной очистки хранилища (`clearCategory`).
   - Проверка вычисления объёмов хранилища (`getStorageBreakdown`).
2. **Модульные тесты:** `frontend/tests/cached-browse.test.cjs` (новый, 13 тестов):
   - Регрессия на баг воспроизведения: `cachedToTrack` берёт числовой `id`
     (`id`/`fileId`), а не `file_id`; для мусорной строки даёт `null`, не `NaN`.
   - Построение дерева `Metallica → Reload → Song1`, разбиение артиста по
     альбомам, объединение вариантов написания имени, бакеты «Без исполнителя».
   - Пропуск строк без пригодного `id`; отсутствие выдуманной обложки у
     безымянных бакетов.
   - Формы карточек под существующие рендереры каталога; namespace-id кэш-карточек.
3. **Общий тестовый прогон:** 110 тестов `npm test` → 104 успешно. 6 падений
   **предсуществующие и не связаны с правкой** (проверено на чистом дереве через
   `git stash`): SSE-транскод (`business-logic.test.cjs` 26–29), `confirm` в
   импорте VFS (`async-fixes.test.cjs` 16), 429 с HTTP-date (`edge-cases.test.cjs` 60).
4. **Сборка production-бандла:** `npm run build` — успешно, 1689 модулей.
   Бандл пересобран на диске; сервер раздаёт `frontend/dist` на лету, поэтому
   изменения видны в мобильном приложении после перезагрузки страницы
   (APK пересобирать не нужно — приложение работает в remote-режиме).
