Проведён глубокий статический и структурный аудит всех модулей backend/app, frontend/src и mobile/android на соответствие десятке рисков OWASP.

Категория OWASP Реализованные механизмы защиты в T-Music Статус
A01: Broken Access Control Ролевые зависимости FastAPI (get_admin_user, get_catalog_user, get_stream_user). Path Traversal защита в SPA и VFS через resolve() + is_relative_to(). BOLA/IDOR предотвращен фильтрацией по owner_id == user.id в плейлистах и истории. Защищено
A02: Cryptographic Failures Пароли защищены Argon2id (m=64MB, t=3, p=1). Сессионные токены JWT с привязкой uid, jti, tv (token_version). Поблочное AES-256-GCM шифрование медиафайлов Telegram. Хранилище паролей и секретов изолировано. Защищено
A03: Injection (SQL / Command) Все запросы к БД параметризованы через SQLAlchemy ORM. Вызовы ffmpeg / ffprobe производятся через массив аргументов без shell=True. Проверены все вызовы execute(). Защищено
A04: Insecure Design Защита от DoS на уровне тел запросов (BodySizeLimitMiddleware: 1MB JSON, 11MB обложки, 257MB бэкапы). Ограничение параллелизма KDF через семафор PASSWORD_HASH_CONCURRENCY=2. Защищено
A05: Security Misconfiguration Заголовки безопасности: CSP без unsafe-inline для скриптов, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, HSTS при включенном HTTPS. (Замечание по LAN CORS описано ниже). Внимание (LAN)
A06: Vulnerable Components Все пакеты в backend/requirements.txt строго зафиксированы версиями (pinned: argon2-cffi==25.1.0, PyJWT==2.15.1, cryptography==50.0.1). Уязвимых или устаревших зависимостей не обнаружено. Защищено
A07: Identification & Auth Failures Защита от тайминг-атак (timing_equalizer_hash). Лимитер запросов на /api/auth/login (10 req/min). Мгновенный отзыв токенов при смене пароля. Двухфазная миграция устаревших bcrypt паролей. Защищено
A08: Software & Data Integrity Строгая валидация Pydantic v2 на всех роутах. Отсутствие небезопасного pickle / десериализации. Защищено
A09: Logging & Monitoring Пароли, токены и приватные ключи автоматически маскируются значением [redacted] при логировании. Все действия администраторов протоколируются в AdminAuditEvent. Защищено
A10: SSRF Сервис загрузки обложек (cover_cache_service.py) выполняет резолвинг DNS через is_safe_host() и блокирует доступ к loopback, RFC 1918 и облачным метаданным (169.254.169.254). SVG блокируется от Stored XSS. Защищено

Результаты анализа периметра API:

  • Mass Assignment исключён: Модели создания и обновления используют Pydantic schemas (например, UserPatch допускает только role, is_active, new_password). Прямая запись сырых **request.dict() в ORM-модели отсутствует.
  • Rate Limiting настроен: Централизованный sliding-window лимитер (120 req/min общий, 10 req/min для авторизации, 30 req/min для приёма клиентских логов).
  • Экранирование ошибок: Глобальный обработчик unhandled_exception_handler в main.py перехватывает любые непредвиденные сбои и возвращает нейтральный {"detail": "Internal server error."}, скрывая детали SQL или структуры сервера.
  • Стриминг аудио: Роут GET /api/stream/{file_id} защищён зависимостью get_stream_user. Для внешних плееров без поддержки заголовков выдаётся одноразовый токен со скоупом scope="stream" и сроком жизни 10 минут.

🔐 Промпт №4: Проверка логики аутентификации и авторизации
Argon2id + Strict JWT + CSRF
  • Argon2id: Инициализирован экземпляр PasswordHasher(time_cost=3, memory_cost=65536, parallelism=1, type=Type.ID). Запись новых хешей всегда формирует $argon2id$v=19$.... Проверка хешей валидирует допустимые диапазоны до старта вычислений.
  • Строгий JWT: Требуются claims: sub, exp, iat, jti, uid, tv. При несовпадении uid с текущим ID пользователя в базе или несоответствии token_version токен моментально признаётся недействительным. Зарезервированные поля защищены от переопределения.
  • CSRF Double-Submit: Все мутирующие HTTP-запросы из браузера валидируются по совпадению cookie csrf_token и заголовка X-CSRF-Token с fail-closed поведением.
[MEDIUM] Конфигурация CORS для локальной сети (CORS_ALLOW_LAN) Medium
Файл: backend/app/main.py:369-374
При включенной настройке CORS_ALLOW_LAN=True разрешены запросы со всех частных подсетей (192.168.x.x, 10.x.x.x, 172.16-31.x.x) с заголовками allow_headers=["*"] и allow_credentials=True. Хотя CSRF-токен защищает мутации данных, злоумышленный сайт при посещении пользователем в локальной сети может попытаться считывать метаданные API через GET.
Рекомендация: Для продуктивного развертывания отключать CORS_ALLOW_LAN=false и указывать конкретный белый список доменов в ALLOWED_ORIGINS.
🎯 Промпт №5: Нулевые указатели, NaN и граничные условия
Граничные условия защищены

Проведён поиск деления на ноль, парсинга невалидных чисел, обращений к полям без проверки на None/null:

  • Деление на ноль: В аналитике и расчёте процента воспроизведения (played_sec / duration) везде предусмотрены проверки if track_duration and track_duration > 0: ... else: 0. Статические совпадения сканера в DLL-файлах ffmpeg относятся к внутренним библиотекам libav.
  • Парсинг чисел во фронтенде: В playerStore.js громкость парсится с валидацией Number.isFinite(storedVolume) с ограничением Math.max(0, Math.min(1, storedVolume)).
  • Граничные условия списков: Все параметры пагинации снабжены валидаторами ge=0, le=1000. Пустые списки треков обрабатываются корректно без падений.
⚡ Промпт №6: Асинхронность, конкурентность и Event Loop
Устранено
[MEDIUM → УСТРАНЕНО] Синхронный запуск ffprobe и запись на диск в асинхронном воркере Устранено
Файлы: backend/app/services/transcoding_service.py, backend/app/utils/ffmpeg_transcoder.py
Было: Внутри асинхронной корутины воркера _worker_loop вызов get_mp3_duration выполнял блокирующий subprocess.run([ffprobe, ...]), а также синхронный with open(output_path, 'wb') as f: f.write(...) на основном цикле событий asyncio.
Решение: Запись временных файлов и MP3 на диск вынесена в await asyncio.to_thread(_write_file, ...) / await asyncio.to_thread(_write_bytes_sync, ...). Вычисление длительности ffprobe обёрнуто в await asyncio.to_thread(get_mp3_duration, str(output_path)). Блокировка Event Loop полностью исключена. Покрыто тестом test_transcode_track_offloads_io_and_duration_probe.
[LOW / Minor → УСТРАНЕНО] Синхронное сканирование папки в _cleanup_cache Устранено
Файл: backend/app/services/transcoding_service.py
Решение: Сканирование файлов кэша для подсчёта суммарного размера и удаление устаревших файлов вынесено в тред-пул через await asyncio.to_thread(self._cleanup_cache), а также сохранение метаданных через await asyncio.to_thread(write_cache_manifest, ...).
Конкурентность во фронтенде (Zustand Stores) Надёжно
В favoritesStore.js внедрена система очередей pending.get(fileId) и версионирования эпох epoch/revision, что полностью предотвращает состояния гонки при быстрых повторных кликах пользователя и отменяет устаревшие ответы сети.
🧠 Промпт №7: Охотник за логическими ошибками
Критических логических дыр нет
  • Защита от самоблокировки системы: В admin_router.py при изменении роли или деактивации пользователя проверяется _active_admin_count(db) — невозможно деактивировать или снять права с последнего активного администратора.
  • Целостность плейлистов: В PlaylistService.mirror операция зеркалирования защищена блокировкой строки владельца with_for_update(), что исключает возникновение дубликатов при параллельных запросах.
  • Сравнение типов: Во всех критических местах проверки отсутствия значений используется is None, что предотвращает баги при передаче значений 0, пустой строки или False.
🛠️ Промпт №8: Проверка обработки ошибок и откатов транзакций
Откат транзакций гарантирован
  • Гарантия Rollback: Все сервисы мутаций (playlist_service.py, vfs_import_service.py, auth_service.py) оборачивают запись в базу в блок try ... except Exception: db.rollback(); raise. База данных никогда не остаётся в «зависшем» несогласованном состоянии.
  • Типизированные исключения: Вместо неспецифических ошибок созданы выделенные классы: VfsImportError, ApiError во фронтенде с дифференциацией сетевых ошибок (0), 401, 403, 422 и 500.
  • Штатные исключения (try/pass): Сканером выявлено 37 блоков except: pass. Детальный аудит показал, что все они находятся в блоках удаления временных файлов (unlink(missing_ok=True)) или закрытия фоновых задач при shutdown, и не влияют на бизнес-логику.
