⚠️ Критический вопрос: Пароль администратора (123) на публичном VPS
Согласно решению владельца проекта от 2026-10-02, локальный пароль админа зафиксирован как 123. Однако на публичном сервере в интернете боты непрерывно сканируют порты 80/443 и атакуют словарь паролей (admin:123 — один из первых в базах словарей). Бот получит доступ с первой же попытки.

Решение плана (Вариант А — Рекомендуемый): Внутри приложения пароль остаётся 123, но на внешнем уровне Nginx вход в панель /api/admin и эндпоинт /api/auth/login закрывается HTTP Basic Auth шлюзом (или Cloudflare Turnstile / персональным VPN WireGuard/Tailscale). Боты без логина и пароля внешнего шлюза вообще не дойдут до приложения FastAPI.
🛡️ Предотвращение обхода UFW через Docker
Docker на Linux по умолчанию вставляет правила в iptables перед правилами брандмауэра ufw. Если порт проброшен как 8005:8005, он открыт всему интернету напрямую. В релизной конфигурации: порт привязывается исключительно к локальному интерфейсу 127.0.0.1:8005:8005, а весь внешний трафик идёт строго через Nginx с валидацией SSL/TLS и фильтрацией ботов.

🔑 2. Анализ и защита сессии Telegram

Сессия Telegram (session_string, api_hash, api_id) даёт полный доступ к аккаунту Telegram владельца и его «Избранному» (Saved Messages). Защита этих данных — наивысший приоритет.

Вектор атаки / Риск Состояние в коде Реализованная защита и план усиления
Кража через утечку базы данных (SQL Dump) Защищено Все сессии хранятся в таблице tg_accounts зашифрованными симметричным шифром Fernet (ключ sha256(SESSION_SECRET)). Без секретного ключа из music.env дамп БД бесполезен.
Запуск с дефолтным или пустым SESSION_SECRET SEC-01: Уязвимость Внедряется: При ENVIRONMENT=production сервер не запустится (Fail-Fast), если SESSION_SECRET не задан, короче 32 символов или равен CHANGE_ME. Это исключает хранение сессий в открытом виде.
Утечка сессии через API бэкенда Защищено Проверены все роутеры: ни один эндпоинт (включая админку) не возвращает поля session_string и api_hash. В API отдаются только ID, имя и флаги статуса соединения.
Кража через VFS SQL Import Защищено Парсер vfs_import_service.py парсит из tg_accounts только id и name. Секретные строки сессий игнорируются и не попадают во временные файлы или SQLite.
Утечка в логи приложения Защищено В логгере logs_router.py и middleware маскируются поля session_string, api_hash, token, password строкой [redacted]. Ротированные архивы шифруются AES-256 (pyzipper).
Чтение из памяти процесса (RAM Dump) Защищено Контейнер работает от непривилегированного пользователя tmusic, включены no-new-privileges: true и cap_drop: ALL. Сессия загружается в память Pyrogram без создания временных SQLite-файлов.
Перехват сетевого трафика (MITM) Требует TLS Внедряется: Принудительный HTTPS с HSTS, флаг cookies COOKIE_SECURE=true, запрещающий передачу cookie сессии по незащищенному HTTP.

💻 4. Детализация кода и конфигураций

1. Fail-Fast защита секретов в backend/app/core/config.py

# Добавление в config.py для строгой защиты в production:
DISCOVERY_ENABLED: bool = True

# Валидация при загрузке:
if (settings.ENVIRONMENT or "").lower() == "production":
    if not settings.SESSION_SECRET or settings.SESSION_SECRET in ("CHANGE_ME", "secret") or len(settings.SESSION_SECRET) < 32:
        raise RuntimeError(
            "CRITICAL SECURITY CONFIGURATION: SESSION_SECRET must be configured with a "
            "strong 256-bit secret (min 32 chars) in production to protect Telegram sessions. "
            "Generate via: python -c \"import secrets; print(secrets.token_urlsafe(32))\""
        )
    if not settings.SECRET_KEY or settings.SECRET_KEY in ("CHANGE_ME", "secret") or len(settings.SECRET_KEY) < 32:
        raise RuntimeError(
            "CRITICAL SECURITY CONFIGURATION: SECRET_KEY must be explicitly configured "
            "in production. Ephemeral keys are forbidden."
        )

2. Отсечка ботов и сканеров в backend/app/main.py

# Блокировка типичных путей вредоносных ботов без расхода ресурсов на SPA:
_SCANNER_EXTENSIONS = ('.env', '.git', '.php', '.asp', '.aspx', '.sql', '.bak', '.yml', '.yaml')
_SCANNER_PREFIXES = ('/.env', '/.git', '/wp-', '/wordpress', '/actuator', '/phpmyadmin', '/admin.php')

@app.get("/{full_path:path}")
async def serve_spa(full_path: str):
    lower_path = f"/{full_path.lower()}"
    if any(lower_path.endswith(ext) for ext in _SCANNER_EXTENSIONS) or any(lower_path.startswith(pre) for pre in _SCANNER_PREFIXES):
        return JSONResponse(status_code=404, content={"detail": "Not found"})

3. Релизный конфиг Nginx (deploy/nginx/tmusic.conf)

server {
    listen 80;
    server_name music.yourdomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name music.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/music.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/music.yourdomain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;

    # Блокировка известных вредоносных ботов и сканеров по User-Agent
    if ($http_user_agent ~* (sqlmap|nikto|wpscan|masscan|zgrab|nmap|morfeus)) {
        return 403;
    }

    # Защитный шлюз для панели администратора (Вариант А)
    location /api/admin/ {
        auth_basic "Restricted Admin Area";
        auth_basic_user_file /etc/nginx/.htpasswd_admin;
        proxy_pass http://127.0.0.1:8005;
        include /etc/nginx/proxy_params_common;
    }

    # Потоковое аудио — отключение буферизации для мгновенного Range-ответа
    location /api/stream/ {
        proxy_pass http://127.0.0.1:8005;
        proxy_buffering off;
        proxy_http_version 1.1;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Основной прокси к FastAPI
    location / {
        proxy_pass http://127.0.0.1:8005;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

🚀 5. Пошаговый регламент деплоя на VPS (Runbook)

  • 1
    Базовая настройка VPS (Ubuntu/Debian):

    Включение UFW (разрешить только SSH, 80, 443). Установка Docker, Docker Compose, Nginx и Fail2ban.

    sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
  • 2
    Генерация секретов и настройка music.env на сервере:

    Сгенерировать криптостойкие 256-битные ключи для SECRET_KEY, SESSION_SECRET и LOG_ARCHIVE_PASSWORD. Установить права доступа chmod 600 music.env.

    python -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(32))"
python -c "import secrets; print('SESSION_SECRET=' + secrets.token_urlsafe(32))"
python -c "import secrets; print('LOG_ARCHIVE_PASSWORD=' + secrets.token_urlsafe(24))"
  • 3
    Инициализация сессии Telegram:

    Запуск python scripts/create_session.py на сервере или перенос готовой зашифрованной базы. Проверка шифрования:

    python scripts/secure_tg_accounts.py --check
# Должно вывести: Check complete: 0 account(s) with plaintext credentials.
  • 4
    Запуск контейнеров и выпуск SSL сертификата:

    Запуск контейнеров через docker compose -f docker-compose.prod.yml up -d --build. Получение бесплатного Let's Encrypt сертификата через certbot и применение конфига Nginx.

    sudo certbot certonly --webroot -w /var/www/certbot -d music.yourdomain.com
sudo nginx -t && sudo systemctl reload nginx
  • 5
    Финальная верификация безопасности:

    Проверка статуса здоровья (/health), корректности заголовков (HSTS, CSP, nosniff), проверка блокировки брутфорса через Fail2ban.
