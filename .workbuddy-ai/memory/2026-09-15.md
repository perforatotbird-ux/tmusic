# 2026-09-15

## Security audit T-Music (OWASP Top 10)
- Проведён полный аудит безопасности проекта tmusic (backend 36 py, frontend 14 исходников, скрипты, Docker). Отчёт: `.sec_audit/SECURITY_AUDIT.md`.
- **КРИТИЧЕСКАЯ находка (подтверждена PoC на реальном uvicorn):** path traversal в SPA catch-all роуте `serve_spa` (`backend/app/main.py:105-110`) — `GET /..%2F..%2Fmusic.env` без аутентификации отдаёт все секреты; возможен выход за корень проекта. PoC: `.sec_audit/poc_path_traversal.py`, `.sec_audit/poc_server.py`.
- Критично #2: дефолтные креды admin/admin123 + PIN 1234 создаются миграцией `scripts/migrate_data.py:330-343` с несолёным SHA-256; legacy-путь верификации SHA-256 без соли в `app/core/security.py`; нет эндпоинта смены пароля.
- Средние: публичный `GET /api/library/cover` (без auth, DNS-rebinding TOCTOU, disk-fill), CSP unsafe-inline, Docker от root, auth-события не логируются, `is_rate_limited()` реализован но не используется, python-jose CVE-2024-33663/33664 (не эксплуатируются при HS256), зависимости не пинируются.
- Хорошо: SQLAlchemy ORM везде (нет SQLi), SSRF-фильтр обложек, magic-bytes валидация (SVG запрещён), AES-256-GCM+HKDF+Argon2id, bcrypt, JWT jti-ревокация, React без dangerouslySetInnerHTML, XML не парсится (XXE неприменим).
- Рекомендованный фикс serve_spa: `(FRONTEND_DIST / full_path).resolve()` + `is_relative_to(FRONTEND_DIST.resolve())`, либо `StaticFiles(html=True)` вместо ручного catch-all.

## Выполнение рекомендаций аудита (та же сессия, по запросу пользователя)
- **Все рекомендации выполнены.** Ключевое:
  - C-1 исправлен в `app/main.py` (resolve+is_relative_to) — PoC повторно прогнан: `..%2Fmusic.env` больше не отдаёт секреты (SPA-shell вместо файла); CSP `script-src 'self'` без unsafe-inline; удалён X-XSS-Protection; HSTS при COOKIE_SECURE; rate-limit middleware `/api/*` 120/мин, `/api/auth/login|pin` 10/мин; предупреждение при REQUIRE_AUTH=false.
  - C-2: дефолтные креды удалены из `scripts/migrate_data.py`; новый `app/services/bootstrap.py` (`ensure_admin_bootstrap`) применяет `ADMIN_PASSWORD_HASH` (bcrypt) при старте, чистит legacy PIN; новый CLI `scripts/init_admin.py`; эндпоинт `POST /api/auth/change-password`.
  - Пароль панели установлен по запросу: bcrypt-хэш записан в `music.env` → `ADMIN_PASSWORD_HASH=$2b$12$***REDACTED***` (открытый пароль удалён из документа). Проверено verify+Bootstrap на SQLite.
  - SECRET_KEY в `music.env` ротирован (старый был скомпрометирован через C-1). SESSION_SECRET НЕ ротирован — на нём завязано шифрование TG-сессий в БД; ротация потребует перевыпуска сессий (scripts/create_session.py).
  - TG-ключи в БД теперь шифруются Fernet (sha256(SESSION_SECRET)): `app/tg/manager.py` — `encrypt_session_string`/`is_encrypted` + self-heal при старте (plaintext → encrypted), api_hash тоже дешифруется; офлайн-утилита `scripts/secure_tg_accounts.py`; миграция шифрует при копировании.
  - security.py: PyJWT вместо python-jose; несолёный SHA-256 отклоняется; солёный legacy — только миграция с авто-апгрейдом на bcrypt; dummy-bcrypt против timing-enum.
  - auth_service.py: логирование tmusic.auth, PIN-lockout на аккаунт (как у пароля), change_password.
  - `GET /api/library/cover` закрыт `get_current_user`; LIKE-escape в artist/album репозиториях (`app/utils/like.py`); RAM-кэш с байтовым лимитом (RAM_CACHE_MAX_BYTES); Dockerfile non-root+HEALTHCHECK; compose no-new-privileges+cap_drop; requirements.txt запинены; tests/test_api.py переписан без дефолтных кредов.
- Верификация: 11/11 DB-независимых тестов (test_security.py, test_stream.py) зелёные; JWT/bcrypt/Fernet раундтрипы ОК; Bootstrap 3 кейса ОК; rate-limit подтверждён (429 после 10); cover/artists без токена → 401. Интеграционные тесты test_api.py/test_library.py не прогонялись — PostgreSQL (5433) и Docker в этой среде выключены.
